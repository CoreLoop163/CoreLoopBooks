\section{树}
在\ref{sec:数据结构}节中，我们已经对“什么是树”有了一个感性的认知。与现实中的大树类似，数据结构中的树也是一种由根开始分叉生长的结构。

下面给出树的定义。
\begin{definitionbox}

    \term{树}是$n$（n>=0）个数据元素组成的有限集合，当n=0时，称为\term{空树}。任何一棵非空树都满足以下条件：
    
    \begin{enumerate}
        \item 有且仅有一个数据元素无前驱，称为\term{根节点}；
        \item 除根节点外，其余每个数据元素都有且仅有一个前驱节点，称为\term{父节点}；
        \item 每个数据元素可以有零个或多个后继节点，称为\term{子节点}。
    \end{enumerate}

\end{definitionbox}

由以上定义可知，对于一棵非空树中的任意一个节点，以该节点为根节点，连同该节点的所有后代节点在内所构成的仍是一棵树，称为原树的一棵\term{子树}。
通常认为一棵树本身是自己的子树。很少存在一些场景会关心树中节点的各个子树从左至右是否有次序（即互换后还能不能认为是同一棵树），但通常将节点有次序的树称为
\term{有序树}，节点没有次序的树称为\term{无序树}。

“树”这个逻辑结构该如何实现？如果采用链表类似的思想，每个节点除保存数据外，再保存所有指向其孩子节点的指针，像这样：
\begin{cppcode}
    struct TreeNode {
        ElemType data;
        TreeNode* child1;
        TreeNode* child2;
        TreeNode* child3;
        ...
    }
\end{cppcode}
显然，我们无法预知每个节点有多少孩子节点，因此无法为TreeNode结构定义固定数量的孩子节点指针。
熟悉C++的同学可能会想到，可以使用一个不定长数组，将节点的所有孩子指针保存到该数组中：
\begin{cppcode}
    struct TreeNode {
        ElemType data;
        std::vector<TreeNode*> childs;  // childs是一个不定长数组，childs[0], ..., childs[n]分别表示该节点的各个孩子节点指针
    }
\end{cppcode}
如图\ref{fig:用不定长数组表示树的孩子}所示。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.47\textwidth]{assets/pics_and_ppts/ch4/树的不定长数组表示.png}
    \caption{用不定长数组表示树的孩子}
    \label{fig:用不定长数组表示树的孩子}
\end{figure}
这是完全可行，也非常自然的一种树的表示方式。但本书不要求大家熟悉C++，因此我们给出树的另一种表示方法，也是更高效的
\term{孩子-兄弟表示法（First Child - Next Sibling Representation）}。该方法存储每个节点的第一个孩子的指针，以及下一个兄弟的指针：
\begin{cppcode}
    struct TreeNode {
        ElemType data;
        TreeNode* first_child;
        TreeNode* next_sibling;
    };
\end{cppcode}
如图\ref{fig:树的孩子-兄弟表示法}所示。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.6\textwidth]{assets/pics_and_ppts/ch4/树的孩子-兄弟表示法.png}
    \caption{树的孩子-兄弟表示法}
    \label{fig:树的孩子-兄弟表示法}
\end{figure}


显然该表示法下，只要拿到根节点指针，就能找到树中任何一个节点。因此，可以用根节点指针表示一棵树。如：
\begin{bulk}
    TreeNode* root; 
\end{bulk}
root这个对象既可以理解为树的根节点的指针，又可以理解为以root节点为根的一棵树。\\
\begin{notebox}{提示}
    图\ref{fig:用不定长数组表示树的孩子}与图\ref{fig:树的孩子-兄弟表示法}逻辑上是同一棵树，只不过物理指针的含义不同。
\end{notebox}


有了以上的内容介绍，我们来做一点有意思的事情（当然你大可以放心地跳过）：用孩子-兄弟表示法尝试实现操作系统的目录树。

\subsection{*目录树的简单实现}
我们已经知道，操作系统对目录的管理其实就是一棵树。用户随时可能在任何目录新建目录、删除某个目录，我们暂且不考虑文件。并假设目录节点的“数据”只有一个字符串
类型的成员，表示目录的名字，如“电影”等。以下代码实现了简单的新建目录、删除目录的操作，具体过程请结合注释。

\begin{cppcode}
    // 在目录Dad中，新建一个名为name的目录
    void DirInsert(TreeNode* Dad, char* name) {
        // 函数实现：创建一个新节点，将其加入Dad的孩子链表末尾
        TreeNode* new_node = (TreeNode*)malloc(sizeof(TreeNode));
        strcpy(new_node->name, name);
        new_node->first_child = NULL;
        new_node->next_sibling = NULL;

        // Dad原本是空目录，则需要更改first_child指针。
        if(Dad->first_child == NULL) {
            Dad->first_child = new_node;
            return;
        }

        // 原本不是空目录，修改next_sibling指针。
        TreeNode* last_child = Dad->first_child;
        while(last_child->next_sibling != NULL) {
            last_child = last_child->next_sibling;
        }
        last_child->next_sibling = new_node;
        return;
    }

    // 销毁一个节点及其所有后代
    void DestroyTree(TreeNode* root) {
        if(root == NULL) return;
        // 先递归销毁其子树
        DestroyTree(root->first_child);

        // 再释放根节点
        free(root);
    }

    // 在目录Dad中，删除目录to_del
    void DirDelete(TreeNode* Dad, TreeNode* to_del) {
        // 函数实现：先把to_del从父节点的孩子链表中摘掉，再销毁以to_del为根的整棵树
        if(Dad == NULL) {
            return;
        }
        // 要删除的就是第一个孩子节点，需要更新first_child指针
        if(to_del == Dad->first_child) {
            Dad->first_child = to_del->next_sibling;;
            // 注意这里不能简单地free(to_del)，因为该目录中可能还有若干目录，目录中可能还有目录，因此要递归销毁。
            DestroyTree(to_del);
            return;
        }

        // 找到要删除的节点的前一个兄弟节点
        TreeNode* pre = Dad->first_child;
        while(pre->next_sibling != to_del) {
            pre = pre->next_sibling;
        }

        // 修改链条，类似单链表的删除操作
        pre->next_sibling = to_del->next_sibling;
        // 注意同样要递归销毁
        DestroyTree(to_del);
        return;
    }
\end{cppcode}

\begin{notebox}{提示}
    以上例子也给了我们一个重要提示：树中每个节点的子节点很多时候不能单纯的看成一个节点，而是要看成一棵子树。因此与树相关的操作，很多都会涉及到递归，这一点非常重要。
\end{notebox}

\subsection{树的一些基本概念与性质}
我们回到逻辑上的数据结构：树。树中有一些大家常用的专业术语与性质，我们在这里列出。\\
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.6\textwidth]{assets/pics_and_ppts/ch4/一棵树.png}
    \caption{}
    \label{fig:一棵树}
\end{figure}

a）树中，一个节点拥有的子树数量称为\term{节点的度}。一棵树中所有节点的度的最大值称为这棵\term{树的度}。

b）树中度为0的节点称为\term{叶子节点}，简称\term{叶节点}。显然叶节点没有孩子节点。不是叶子节点的节点称为\term{非叶节点}。\\
图\ref{fig:一棵树}中，节点A、B的度均为3，整棵树的度为3；节点E、F、K、H、I、L、M的度为0，是叶子节点。\\
c）可以看出树是一种具有层次结构的数据结构。根节点处于最高层，通常定义根为第1层，根的孩子为第2层。若某节点处在第i层，其子树的根节点就处在第i+1层。

d）\term{节点的深度}通常定义为节点的所在层次；而\term{节点的高度}通常是指从最底层叶子节点（高度为1）开始逐层累加至该节点时的高度值。所有节点的深度
的最大值称为\term{树的深度}或\term{树的高度}。即
\begin{bulk}
    \begin{center}
        树的高度 = max\{所有节点的深度值\} = max\{所有节点的高度值\}
    \end{center}
\end{bulk}

图\ref{fig:一棵树}中，节点A的深度为1，高度为4；节点B的深度为2，高度为3；节点K的深度为4，高度为1。整棵树的深度，或称整棵树的高度，为4。

\begin{notebox}{提示}
    1.有些人喜欢将根节点的高度定义为0，本书若无特别说明，默认按照根节点高度为1来定义。\\
    2.注意区分节点与树的深度和高度：节点的高度和节点的深度通常不是一回事；而树的高度和树的深度一定是相等的。
\end{notebox}

e）类似现实中的说法，数据结构中多棵树同样可以构成\term{森林}。

\minisection{树的重要性质}
我们首先给出一个重要性质：对于任何一棵非空树，其节点数$n$与边数$e$一定有
\[
    n = e + 1
\]
成立。显然，当$n=1$时，树只有一个根节点，上式显然成立。此后，如图\ref{fig:节点数等于边数加一规律图}所示，从任何一个节点引出一条新的边，
都会使得边数$e$和节点数$n$同时加一，因此等式仍然成立。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\textwidth]{assets/pics_and_ppts/ch4/节点数等于边数加一规律图.png}
    \caption{}
    \label{fig:节点数等于边数加一规律图}
\end{figure}
另外，不难发现，每从节点引出一条新的边，会使边数加一的同时，会使该节点的度数加一，所以不难得知，所以对任何一棵非空树，所有节点的度数之和即等于
该树的总边数$e$。

整理以上两个结论，有：对任何一棵非空树，都有以下结论成立：
\begin{center}
    树的边数e = 树中所有节点的度数之和 = n - 1（n为树的节点数）
\end{center}

\begin{notebox}
    由以上的思维过程也可以反推出一件事：树中度为n的节点，会为树“贡献”n条边。比如：一棵度为3的树，若已知度为3、2、1的节点分别有7、5、8个，则该树的边数一定是
    \[
        7 * 3 + 5 * 2 + 8 * 1 = 39
    \]
    于是可知该树的节点数为$39+1=40$，于是叶节点的数量就是$40-7-5-8=20$个。
\end{notebox}


\section{二叉树的基本内容介绍}
简单地说，“最多两个分叉的树”就是二叉树。一棵普通的二叉树本身通常难以在实际问题中应用上，但是它却是后面一些非常有趣的特殊二叉树（如
\term{二叉查找树}、\term{哈夫曼树}、\term{堆}等）的理论基础。所以我们有必要首先进行一些理论铺垫。
\begin{definitionbox}
    \term{二叉树}要么是一棵空树，要么是一棵：\\
    
    由根节点以及它的两棵子树构成的树，这两棵子树有左右位置之分，分别称为\term{左子树}和\term{右子树}，并且左子树和右子树依然是一棵二叉树。
\end{definitionbox}
可以看到，二叉树是\term{递归定义}的，即用二叉树自身来定义二叉树。
如图\ref{fig:几棵不同的二叉树}所示的几棵树都是二叉树，根据图中文字介绍，大家也能进一步体会二叉树的“递归定义”。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=1.0\textwidth]{assets/pics_and_ppts/ch4/几棵不同的二叉树.png}
    \caption{几棵不同的二叉树}
    \label{fig:几棵不同的二叉树}
\end{figure}
请注意，由图\ref{fig:几棵不同的二叉树}我们可以看出，二叉树的递归定义中，递归边界就是二叉树为一棵空树，这一点对我们二叉树中的诸多编程思想尤其重要，大家在后面
将会慢慢体会到。
显然二叉树的度只可能是0、1或2，二叉树中每一个节点的度也只可能是0、1或2。



\begin{notebox}{提示}
    “二叉树”与“度为2的有序树”有如下区别：\\
    1. 二叉树的度未必是2，还可能是0或1；\\
    2. 二叉树即使只有一个孩子节点，该节点也要区分左右。而度为2的有序树，其“有序”是兄弟之间的位置有序，若某个节点是“独生子女”，则其位置是唯一确定的，不分左右。
    二叉树明确区分孩子的左右位置，这是因为在更多的场景下这是有用的，在后面的内容中我们将有所体会。
\end{notebox}

有两种比较丰满的二叉树需要特别关注：满二叉树与完全二叉树。

如果二叉树中的任意一层节点数都达到了当层能达到的最大节点数，这种二叉树称为\term{满二叉树}；如果除最下面
一层外，其余层都达到了当层最大节点数，并且最后一层的节点都一个挨一个地挤在左边，则二叉树称为\term{完全二叉树}。显然满二叉树一定都是完全二叉树。

图\ref{fig:一些满二叉树与完全二叉树}展示了一些满二叉树与完全二叉树。

\subsection{二叉树的实现}
\label{subsec:二叉树的实现}
\minisection{将二叉树存储为二叉链表}
有了链表的思维，相信大家非常自然地就能想到二叉树的实现方式：树的节点设两个指针分别指向其左孩子和右孩子如下所示：
\begin{cppcode}
    struct BTreeNode {
        ElemType data;
        BTreeNode* lchild;  // 左孩子的指针
        BTreeNode* rchild;  // 右孩子的指针 
    };
\end{cppcode}
这正是二叉树最为经典的实现方式，这种物理结构也称为\term{二叉链表}，它与普通的单链表相比“多分出了一个叉”。

正如本节之初所指出，二叉树的实际应用在于一些有趣的特殊二叉树。人们对队列、栈等数据结构有“入队、出队、入栈”等常见操作的定义，是因为它们切实有用，有
重要的实际意义，而普通二叉树几乎不存在实际应用，因此通常不会为它定义一些常见操作，以上介绍的理论，是为了后面的特殊二叉树服务。此处如果你感兴趣，可以
尝试完成下面的“思考”。

\begin{thinkbox}
    建立一棵你中意的二叉树，并遍历这棵树，打印所有节点的数据内容。
\end{thinkbox}

\minisection{二叉树的顺序存储}
基于二叉树有上下的层次关系以及左右的次序关系，如果我们从上到之下、从左到右地为二叉树的每一个节点依次编号，就可以将这些
节点依次存储在数组中的对应下标之处，如图\ref{fig:二叉树的顺序存储}所示，我们这里遵循多数人的习惯，根节点从1开始编号，即从数组下标1处开始存储，而非从0。根据规律不难
得出，\textbf{在这种存储方式下，任一节点i，其父节点的编号一定是\(\left\lfloor \frac{i}{2} \right\rfloor\)（前提是i>1, 即该节点有父节点）；并且其左孩子如果存在的话，
编号一定是2i，右孩子如果存在的话，编号一定是2i+1。}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.95\textwidth]{assets/pics_and_ppts/ch4/用数组表示二叉树.png}
    \caption{二叉树的顺序存储}
    \label{fig:二叉树的顺序存储}
\end{figure}


这种表示法可以由以下代码实现：
\begin{cppcode}
    struct BTreeNode{
        ElemType data;
        int valid;  // 该节点是否存在
    }; 
    BTreeNode nodes[MaxSize];   // 该数组中保存的就是二叉树的所有节点
\end{cppcode}

\begin{notebox}{提示}
    一般情况下每个节点还需要一个字段valid标识是否有效。但如果你存放的数据满足某种特点，比如一定都是正整数，那么你也可以不要valid字段，而是通过将数据的值
    置为，如-1，来表示该位置处节点不存在。
\end{notebox}

二叉树的这种存储方式的问题在于，即使某个节点不存在，也要浪费一个编号位，最坏情况下，当二叉树形状趋于深度为h的一条直线时，我们用约\(2^h\)个空间仅存储了约h个数据。

经过观察不难发现，\textbf{该表示法对完全二叉树（以及满二叉树）非常友好}。因为完全二叉树的节点从上到下、从左到右是连续的，不存在空缺的编号。在介绍{\color{red}
\textbf{后面的内容时}}，我们也能看到该表示法在完全二叉树中的妙用。\\

在进入本章真正有趣的部分之前，我们还要进行一场最后的理论准备：二叉树的遍历。

\subsection{二叉树的遍历}
遍历一个顺序表有多种方式，可以从前向后，也可以从后向前等。类似地，遍历二叉树也有多种方式。常见的、有意义的遍历方式通常有如下4种：\term{层序遍历}、\term{先序遍历}、
\term{中序遍历}、\term{后序遍历}。相信大家最容易想到的遍历方式就是从上到下、从左到右地一个一个节点地访问，这就是\term{层序遍历}。对于
图\ref{fig:用于指出遍历序列的二叉树}中所示的二叉树，层序遍历得到的访问序列是A,B,C,D,E,F,G,H,I,J。

\minisection{二叉树的层序遍历}
对于链式存储的二叉树：
\begin{cppcode}
    struct BTreeNode {
        ElemType data;
        BTreeNode* lchild;  // 左孩子的指针
        BTreeNode* rchild;  // 右孩子的指针 
    };
\end{cppcode}
如何从上到下，从左到右地依次访问每个节点？显然我们仅通过二叉树已有的物理结构是不行的，以图\ref{fig:用于指出遍历序列的二叉树}为例，当我们从A走到B时，
我们知道下一步要访问C，但却没有一种有效的手段优雅地实现接下来的操作。所以我们需要一种手段，每走到一个节点之时，先将其两个孩子按正确的顺序保存起来，它们
就是接下来即将被访问的节点。

承先贤之智，将下法传与思渡者：可使用一个队列，将更上层的节点优先入队，并且确保同层级的节点中，更左边的优先入队。这样，队中节点顺序即是层序遍历的顺序，
依次\uline{出队访问}即可。具体来说，实现二叉树层序遍历的过程如下：
\begin{enumerate}[label=\arabic*）]
    \item 将根节点root加入队列q；
    \item \uline{出队访问}队首节点front\_node；
    \item 如果front\_node有左孩子，先将左孩子入队；
    \item 如果front\_node有右孩子，再将右孩子入队；
    \item 若队列q不空，回到第2）步；否则说明遍历完成，算法结束。
\end{enumerate}
显然第一步将根节点加入队列是毋庸置疑的。而第3）、4）两步，先加入左孩子再加入右孩子，则保证了从左到右的访问顺序。
\begin{insightbox}
    如果你希望从上到下、从\uline{右}到\uline{左}地遍历二叉树，将上面的3）、4）两步交换位置即可。
\end{insightbox}
层序遍历的伪代码如下所示。
\begin{cppcode}
// 对根为root的二叉树进行层序遍历。对每个节点执行visit()函数。
    void LayerOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;
        Queue q;
        InitQueue(q);
        EnQueue(q, root);   // 根节点入队
        while(!Empty(q)) {
            BTreeNode* front_node = NULL;
            DeQueue(q, front_node);     // 队首节点出队，赋值给变量front_node
            visit(front_node);          // 访问front_node
            if(front_node->lchild != NULL) {
                EnQueue(q, front_node->lchild);     // 入队左孩子
            }
            if(front_node->rchild != NULL) {
                EnQueue(q, front_node->rchild);     // 入队右孩子
            }
        }
    }
\end{cppcode}

正是队列的先进先出特性，保证了节点按照从上到下、同层从左到右的顺序被访问。

除层序遍历外，对一棵二叉树的\uline{根节点}、\uline{左子树}和\uline{右子树}也可以有不同的访问顺序。访问一棵二叉树时：
\begin{enumerate}
    \item 若先访问根节点，再访问左子树，最后访问右子树，这种“\uwave{根-左-右}”的遍历方式称为\term{先序遍历}，也称\term{先根遍历}。
    \item 若先访问左子树，再访问根节点，最后访问右子树，这种“\uwave{左-根-右}”的遍历方式称为\term{中序遍历}，也称\term{中根遍历}。
    \item 若先访问左子树，再访问右子树，最后访问根节点，这种“\uwave{左-右-根}”的遍历方式称为\term{后序遍历}，也称\term{后根遍历}。
\end{enumerate}

\begin{notebox}{提示}
    请注意，无论何种访问方式，左子树一定是先于右子树访问。所谓的“先、中、后”指的是“根节点”被“先”访问，还是“中”或“后”访问。
\end{notebox}

\begin{insightbox}
    注意：本内容可能带来一些认知和思维上的启发，但对思渡者来说，可能带来知识记忆上的混乱。\\

    我们为什么不将“根右左”、“右根左”、“右左根”分别定义为先根、中根、后根遍历？这是因为，二叉树的左右子树具有天然的对称性。
    将左与右交换，树的结构和\textbf{本质}并没有发生变化，它描述的还依然是那个“东西”，只是我们人类需要换一个方向去观察和描述它。

    比如你将左边视为头时，[3,5]的\textbf{本质}可以理解为“3在前，5在后的两个数”；而事实上[5,3]同样可以描述“3在前，5在后的两个数”，只需要你把右边视为头，或者
    把“前”定义为后。二者本质相同，只是我们人类观察和理解它的视角不同。

    更进一步地讲，“前”与“后”、“左”与“右”的方向本身就是人为定义的，左子树之所以叫左子树，只是因为我们把“左”定义为了左而已。“左”与“右”本质上并无区别。\\

    我们约定先左，只是因为人类的习惯就是左在前，右在后，这更符合绝大多数人的思维方式。
\end{insightbox}

\minisection{二叉树的先序遍历}
参照图\ref{fig:根节点与左右子树}，先序遍历下，对任何一棵二叉树BT，总是先访问其根节点，再访问其左子树LBT和右子树RBT。递归地，对于LBT和RBT又有同样的规则。
因此递归遍历便是很自然的想法，而递归边界就是某棵子树为空树。先序遍历的递归代码如代码\ref{code:先序遍历二叉树}所示：
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.53\textwidth]{assets/pics_and_ppts/ch4/根节点与左右子树.png}
    \caption{}
    \label{fig:根节点与左右子树}
\end{figure}    

\begin{cppcodeNum}[label={code:先序遍历二叉树}]
    void PreOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;   // 递归边界
        visit(root);    /* 先序遍历，先访问根节点。请注意：这里root应理解为递归过程中访问的每棵子树的根节点，不能仅简单地理解为整棵树的根节点。*/
        PreOrderTravel(root->lchild);   /* 递归遍历左子树。请注意：一定不能写成 visit(root->lchild)。此处场景要把root->lchild看成一棵左子树，而不能仅仅看成一个节点。*/
        PreOrderTravel(root->rchild);   // 递归遍历右子树
    }
\end{cppcodeNum}

返回到E-> B -> A；此时A的左子树已经全部访问完成，根据先序规定的访问顺序：\Circled{1}A\;\Circled{2}A的左子树\;\Circled{3}A的右子树，A及A的左子树已访问完成，接下来访问
A的右子树；\\[0.5em]
走到Tree(C)；\uline{访问C}；\\[0.5em]
走到Tree(F)；\uline{访问F}；\\[0.5em]
走到Tree(I)；\uline{访问I}；\\[0.5em]

\bookmark{bookmark:waypoint-4}{waypoint-4}
可以看出，先序遍历的思想，简单说就是：
\begin{enumerate}
    \item 访问根节点（先根）；
    \item 递归地遍历左子树；
    \item 递归地遍历右子树。
\end{enumerate}
后面的中序、后序遍历，实际上也是这三步，只不过访问根节点的顺序有所不同。\\

请注意，根据先序遍历一定最先访问根节点的特性，对一棵二叉树的先序遍历序列，序列的第一个节点一定是根节点。如上例中，整棵树的遍历序列是
\[
    A,B,D,G,E,H,C,F,I,J
\]
因此A是整棵树的根节点。而对于A的左子树中的五个节点，遍历序列是
\[
    B,D,G,E,H
\]
因此B是该子树的根节点。再如以F为根节点的子树，遍历序列是
\[
    F,I,J
\]
因此F是根节点。

\minisection{二叉树的中序遍历}
参照图\ref{fig:根节点与左右子树}，中序遍历总是先访问左子树，再访问根节点，最后访问右子树。中序遍历的思想与先序遍历类似，只不过在访问根节点之前，要先递归遍历左子树：
\begin{enumerate}
    \item 递归遍历左子树；
    \item 访问根节点（中根）；
    \item 递归遍历右子树。
\end{enumerate}
可以看到，先序、中序、后序在代码上的区别其实就是把“访问根节点”这一操作放在哪一步的区别。中序遍历的代码如下所示。
\begin{cppcode}
    void InOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;   // 递归边界
        InOrderTravel(root->lchild);   
        visit(root);        // 中根
        InOrderTravel(root->rchild);   
    }
\end{cppcode}
我们以图\ref{fig:用于指出遍历序列的二叉树}模拟一遍整个过程。拟用Tree(T)表示以T为根节点的子树。则先序遍历过程如下：\\[0.5em]
走到Tree(A) -> 中根遍历，因此先访问A的左子树，再访问A，最后访问A的右子树。所以暂且不访问A，而是先\\[0.5em]
走到Tree(B) -> 同样地，先访问B的左子树：\\[0.5em]
走到Tree(D) -> 同样地，先访问D的左子树，因此\\[0.5em]
走到Tree(NULL，即D的左孩子) -> 为空树，递归边界，返回到D；该访问D这个节点了：\\[0.5em]
\uline{访问D}，此时D及D的左子树均访问完成，该访问D的右子树了。所以\\[0.5em]
走到Tree(G) -> 依旧先左；
走到Tree(NULL, G的左孩子)；返回到G；\\[0.5em]
\uline{访问G}；此时G及G的左子树均访问完成，该访问G的右子树了。\\[0.5em]
走到Tree(NULL, G的右孩子)；返回到G；\\[0.5em]
返回到D；此时D及D的左右子树均已经访问完成。\\[0.5em]
返回到B；此时B的左子树已访问完成，根据中序遍历规则，该访问根节点了，于是\\[0.5em]
\uline{访问B}；此时B的左子树及B都访问完成，该访问B的右子树了。\\[0.5em]
走到Tree(E)；
走到Tree(H) -> \uline{访问H}；我们不再赘述空子树的访问过程。\\[0.5em]
回到E；\uline{访问E}；\\[0.5em]
回到B -> A；此时A的左子树已经全部访问完成，根据中序规定的访问顺序：\Circled{1}A的左子树\;\Circled{2}A\;\Circled{3}A的右子树，现在A的左子树已经访问
完成，所以接下来\uline{访问A}，然后访问A的右子树。\\[0.5em]
走到Tree(C) -> 左子树为空；\uline{访问C}；\\[0.5em]
走到Tree(F) -> \\[0.5em]
走到Tree(I) -> \uline{访问I}；\\[0.5em]
回到F；\uline{访问F}；\\[0.5em]
走到J；\\[0.5em]
\uline{访问J}；\\[0.5em]
一路回退到A；代码结束。中序遍历得到的序列为D, G, B, H, E, A, C, I, F, J\\

请注意：对于二叉树的中序遍历，根节点的访问总是在左子树和右子树的中间。因此，若已知某棵树的根节点是哪一个，就可以根据根节点在中序序列中的位置，将该中序序列
从根节点处砍成两半，得到左子树和右子树的中序遍历序列。如上面的例子，若已知根节点为A，则立即可以得到：\\
\Circled{1} 根节点左子树的中序遍历序列是
\[
    D, G, B, H, E
\]
\Circled{2} 根节点右子树的中序遍历序列是
\[
    C, I, F, J
\]

\minisection{二叉树的后序遍历}
有了前面的内容，后序遍历就变得很好理解。后序遍历是“左-右-根”，即根节点的访问在最后：
\begin{enumerate}
    \item 递归遍历左子树；
    \item 递归遍历右子树；
    \item 访问根节点（后根）。
\end{enumerate}
代码如下。
\begin{cppcode}
    void PostOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;   // 递归边界
        PostOrderTravel(root->lchild);   // 先递归遍历左子树
        PostOrderTravel(root->rchild);   // 再递归遍历右子树
        visit(root);        // 左子树、右子树均访问完成后，最后访问根节点。
    }
\end{cppcode}
先序遍历是最先访问根节点，而后序遍历是最后访问根节点。因此对后序遍历序列来说，序列中的最后一个节点一定是根节点。
对于图\ref{fig:用于指出遍历序列的二叉树}所示的二叉树，其后序遍历得到的序列为G,D,H,E,B,I,J,F,C,A。

3）插入节点时，可以从根节点开始，将根节点元素与待插元素比较。若待插元素较小（或等于），则说明该节点需要在左子树中插入，此时，若：\\
\Circled{1} 左子树为空，则插入位置已经找到，直接插入；\\
\Circled{2} 左子树非空，则递归地进入左子树，进行同样的操作。\\
反之若待插元素大于根节点，则递归地判断右子树。如此递归进行下去，直至找到正确的位置。具体实现代码如下：
\begin{cppcode}
    void InsertTree(node* &root, int e) {
        if(root == NULL) {
            // 空树，直接插入就行
            node* new_node = (node*)malloc(sizeof(node));
            new_node->data = e;
            new_node->lchild = NULL;
            new_node->rchild = NULL;
            root = new_node;
            return ;
        }
        if(e <= root->data) {   // 待插元素较小
            if(root->lchild == NULL) {  // 左子树为空，说明找到了插入位置
                node* new_node = (node*)malloc(sizeof(node));
                new_node->data = e;
                new_node->lchild = NULL;
                new_node->rchild = NULL;
                root->lchild = new_node;
            } else {    // 递归地进入左子树
                InsertTree(root->lchild, e);    
            }
        } 
        if(e > root->data) {    // 待插元素较大
            if(root->rchild == NULL) {  // 右子树为空，说明找到了插入位置
                node* new_node = (node*)malloc(sizeof(node));
                new_node->data = e;
                new_node->lchild = NULL;
                new_node->rchild = NULL;
                root->rchild = new_node;
            } else {   // 递归地进入右子树
                InsertTree(root->rchild, e);    
            }
        }
    }
\end{cppcode}
事实上，我们将在后面的内容中介绍到，有着这样特点的树叫做\term{二叉查找树}，或者叫\term{二叉搜索树}、\term{二叉排序树}。正如其名，这种数据结构
可以利用节点值之间的大小关系进行较为高效的查找操作，我们将在后面的内容中详细介绍。

\end{exerciseanswer}

（但也有一定难度）的部分，来看一些有实际应用价值的特殊的树。



\section{哈夫曼树与哈夫曼编码}
请思渡者考虑以下最为经典的“合并柴薪”问题：\\

在初始火焰的熔炉周围，散落着$n$堆柴薪，重量分别为$w_1, w_2, ..., w_n$，你每次可以搬运任意两堆柴薪$i$和$j$，将它们合成一堆重量为$w_i+w_j$的新柴薪，
这个过程需要消耗的体力为$w_i+w_j$。显然，$n-1$次搬运之后，就只剩下一堆柴薪了。请问你能否设计最优的合并次序方案，使得耗费的体力最少？并给出消耗的体力值。

例如有3堆柴薪，重量分别为：
\[
    [3, 6, 11]
\]
第一次，你将6和11合并到一起，消耗体力17，还剩两堆柴薪：
\[
    [3, 17]
\]
第二次，你将3和17合并到一起，消耗体力20，只剩一堆柴薪：
\[
    [20]
\]
合并过程一共消耗了 17 + 20 = 37点体力。 显然，若你先合并3和6，则可以达成更少的体力消耗：(3+6)+(9+11)=29点体力。\\

我们看一个稍微复杂一点的例子，五堆柴薪重量分别是：3, 6, 2, 3, 4。我们先随意将它们合并，看看过程中会发生什么。合并过程可以如图\ref{fig:柴薪的合并过程}所示：
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.48\textwidth]{assets/pics_and_ppts/ch4/柴薪的合并过程.png}
    \caption{柴薪的合并过程}
    \label{fig:柴薪的合并过程}
\end{figure}

可以看出，一堆柴薪参与合并后，并不会从后续的合并过程中消失，而是会作为新柴薪的一部分，继续参与后续合并。
例如，初始重量为 3 的柴薪与重量为 6 的柴薪合并后，形成一堆重量为 \(9=3+6\) 的柴薪。虽然新柴薪的重量变成了 9，
但其中仍然包含原来重量为 \uline{3} 的柴薪（9=\uline{3}+6嘛）。因此，当这堆重量为 9 的柴薪再次参与合并时，产生的消耗中仍然包含原来那 3 的重量。也就是说：
\textbf{每堆\uline{原始}柴薪在每次参与合并时，都会为总消耗贡献一次自己的初始重量。}于是，若初始重量为 \(w_i\) 的柴薪参与了 \(k_i\) 次合并，
那么它对总消耗的贡献就是 \(w_i k_i\)。因此，整个合并过程的总消耗可以表示为
\[
W=\sum_{i=1}^{n}w_i k_i
\]

另一方面，由图\ref{fig:柴薪的合并过程}可以看出，原始柴薪越靠后参与合并，其合并次数就越小，如最后的4只参与了1次合并，而第一个3参与了4次合并。因此，自然要将原始重量
更大的柴薪放在更后面合并，这样其参与的合并次数就小，因而总体造成的体力消耗就更小。

基于以上讨论，很容易设计出最优的合并方案：每次从当前所有柴薪中，选出两堆重量最小的进行合并，直至最后合并完成。对于3, 6, 2, 3, 4这五堆柴薪，一种最优的合并
方式如图\ref{fig:柴薪的最优合并方式}所示。

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.45\textwidth]{assets/pics_and_ppts/ch4/柴薪的最优合并过程.png}
    \caption{最优合并过程}
    \label{fig:柴薪的最优合并方式}
\end{figure}
第\Circled{1}步，将最小的2和3合并，消耗体力5，合并后新的柴薪：
\[
    [5, 6, 3, 4]
\]
第\Circled{2}步，将这四堆中最小的3和4合并，消耗体力7，合并后新的柴薪：
\[
    [5, 6, 7]
\]
第\Circled{3}步，将最小的5和6合并，消耗体力11，合并后新的柴薪：
\[
    [11, 7]
\]
第\Circled{4}步，将最小的(也是仅剩的)11和7合并，消耗体力18，合并成最终的一堆柴薪：18。
可以看出，消耗的总体力 = 5 + 7 + 11 + 18 = 41。换个角度，2、3贡献了3次自己的初始重量、6贡献了2次，3和4贡献了2次，因此
$ W=\sum_{i=1}^{n}w_i k_i = (2+3)*3 + 6*2 + (3+4)*2 = 41 $。

相信你早已看出来了，合并的过程其实就构成了一棵二叉树，原始的五堆柴薪就是五个叶子节点，而每堆初始柴薪参与的合并次数$k_i$就是该叶子节点到根节点的\term{路径长度}。
在以上二叉树中，每个节点的数值代表了要搬动这堆柴薪需要消耗的体力。事实上在许多应用中都要类似现象，我们会将树中的节点赋予一个表示某种意义的数值，称为节点的\term{权}。
从树根到一个节点的路径长度与该节点上权值的乘积，就叫做\uline{该节点的}\term{带权路径长度(WPL)}（可以理解为这堆柴薪在后续合并过程中还会贡献的总体力消耗），
而树中所有\uline{叶子节点}的带权路径长度之和就称为\uline{这棵树的}\term{带权路径长度(WPL)}，记为。
\[
\text{WPL}=\sum_{i=1}^{n}w_i k_i
\]
其中$w_i$是第$i$个叶节点的权值，$k_i$是该叶节点到根节点的路径长度。在含有$n$个带权叶节点的二叉树中，带权路径长度最小的二叉树就称为\term{哈夫曼树}。可以看到
在该定义下，“合并柴薪”的问题其实就是求以这n堆柴薪为叶节点的哈夫曼树，其带权路径长度是多少。

通过这个例子，我们也理解了“带权路径长度”以及哈夫曼树的意义。图\ref{fig:柴薪的最优合并方式}所示的过程其实也就是由给定的若干个节点，构造一棵哈夫曼树的过程。这里
将该过程完整地叙述如下：
\begin{enumerate}
    \item 初始化。 根据给定的 \(n\) 个权值，构造 \(n\) 棵仅包含一个节点的二叉树，每个节点的权值分别为 \(w_1,w_2,\ldots,w_n\)。
    此时，每棵树都只有一个根节点，且该节点同时也是叶节点。
    \item 选择与合并。 从当前所有二叉树中，选择根节点权值最小的两棵二叉树，将它们合并为一棵新的二叉树。具体而言，
    以一个新节点作为根节点，将选出的两棵二叉树分别作为新根节点的左、右子树，并将新根节点的权值设置为这两棵树的根节点权值之和。
    \item 更新集合。 将刚刚合并得到的新二叉树加入当前的二叉树集合，同时从集合中移除原先被合并的两棵二叉树。这样，集合中的二叉树数量便减少一棵。
    \item 重复执行步骤 2 和步骤 3，直到当前集合中只剩下一棵二叉树。
    \item 得到哈夫曼树。 最终剩下的二叉树就是所构造的哈夫曼树。其所有叶节点的带权路径长度之和最小。
\end{enumerate}

需要注意的是，选择权值最小的两棵树进行合并时，若存在权值相同的节点，可以任选符合条件的两棵树。不同的选择可能构造出形态不同的哈夫曼树，但所得的最小带权路径长度相同。
