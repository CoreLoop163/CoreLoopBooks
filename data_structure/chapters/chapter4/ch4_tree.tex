\section{树}
在\ref{sec:数据结构}节中，我们已经对“什么是树”有了一个感性的认知。与现实中的大树类似，数据结构中的树也是一种由根开始分叉生长的结构。

下面给出树的定义。
\begin{definitionbox}

    \term{树}是$n$（n>=0）个数据元素组成的有限集合，当n=0时，称为\term{空树}。任何一棵非空树都满足以下条件：
    
    \begin{enumerate}
        \item 有且仅有一个数据元素无前驱，称为\term{根节点}；
        \item 除根节点外，其余每个数据元素都有且仅有一个前驱节点，称为\term{父节点}；
        \item 每个数据元素可以有零个或多个后继节点，称为\term{子节点}。
    \end{enumerate}

\end{definitionbox}

由以上定义可知，对于一棵非空树中的任意一个节点，以该节点为根节点，连同该节点的所有后代节点在内所构成的仍是一棵树，称为原树的一棵\term{子树}。
通常认为一棵树本身是自己的子树。很少存在一些场景会关心树中节点的各个子树从左至右是否有次序（即互换后还能不能认为是同一棵树），但通常将节点有次序的树称为
\term{有序树}，节点没有次序的树称为\term{无序树}。

“树”这个逻辑结构该如何实现？如果采用链表类似的思想，每个节点除保存数据外，再保存所有指向其孩子节点的指针，像这样：
\begin{cppcode}
    struct TreeNode {
        ElemType data;
        TreeNode* child1;
        TreeNode* child2;
        TreeNode* child3;
        ...
    }
\end{cppcode}
显然，我们无法预知每个节点有多少孩子节点，因此无法为TreeNode结构定义固定数量的孩子节点指针。
熟悉C++的同学可能会想到，可以使用一个不定长数组，将节点的所有孩子指针保存到该数组中：
\begin{cppcode}
    struct TreeNode {
        ElemType data;
        std::vector<TreeNode*> childs;  // childs是一个不定长数组，childs[0], ..., childs[n]分别表示该节点的各个孩子节点指针
    }
\end{cppcode}
如图\ref{fig:用不定长数组表示树的孩子}所示。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.45\textwidth]{assets/pics_and_ppts/ch4/树的不定长数组表示.png}
    \caption{用不定长数组表示树的孩子}
    \label{fig:用不定长数组表示树的孩子}
\end{figure}
这是完全可行，也非常自然的一种树的表示方式。但本书不要求大家熟悉C++，因此我们给出树的另一种表示方法，也是更高效的
\term{孩子-兄弟表示法（First Child - Next Sibling Representation）}。该方法存储每个节点的第一个孩子的指针，以及下一个兄弟的指针：
\begin{cppcode}
    struct TreeNode {
        ElemType data;
        TreeNode* first_child;
        TreeNode* next_sibling;
    };
\end{cppcode}
这种表示法如图\ref{fig:树的孩子-兄弟表示法}所示。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.57\textwidth]{assets/pics_and_ppts/ch4/树的孩子-兄弟表示法.png}
    \caption{树的孩子-兄弟表示法}
    \label{fig:树的孩子-兄弟表示法}
\end{figure}


显然该表示法下，只要拿到根节点指针，就能找到树中任何一个节点。因此，可以用根节点指针表示一棵树。如：
\begin{bulk}
    TreeNode* root; 
\end{bulk}
root这个对象既可以理解为树的根节点的指针，又可以理解为以root节点为根的一棵树。\\
\begin{notebox}{提示}
    图\ref{fig:用不定长数组表示树的孩子}与图\ref{fig:树的孩子-兄弟表示法}逻辑上是同一棵树，只不过物理指针的含义不同。
\end{notebox}


有了以上的内容介绍，我们来做一点有意思的事情（当然你大可以放心地跳过）：用孩子-兄弟表示法尝试实现操作系统的目录树。

\subsection{*目录树的简单实现}
我们已经知道，操作系统对目录的管理其实就是一棵树。用户随时可能在任何目录新建目录、删除某个目录，我们暂且不考虑文件。并假设目录节点的“数据”只有一个字符串
类型的成员，表示目录的名字，如“电影”等。以下代码实现了简单的新建目录、删除目录的操作，具体过程请结合注释。

\begin{cppcode}
    // 在目录Dad中，新建一个名为name的目录
    void DirInsert(TreeNode* Dad, char* name) {
        // 函数实现：创建一个新节点，将其加入Dad的孩子链表末尾
        TreeNode* new_node = (TreeNode*)malloc(sizeof(TreeNode));
        strcpy(new_node->name, name);
        new_node->first_child = NULL;
        new_node->next_sibling = NULL;

        // Dad原本是空目录，则需要更改first_child指针。
        if(Dad->first_child == NULL) {
            Dad->first_child = new_node;
            return;
        }

        // 原本不是空目录，修改next_sibling指针。
        TreeNode* last_child = Dad->first_child;
        while(last_child->next_sibling != NULL) {
            last_child = last_child->next_sibling;
        }
        last_child->next_sibling = new_node;
        return;
    }

    // 销毁一个节点及其所有后代
    void DestroyTree(TreeNode* root) {
        if(root == NULL) return;
        // 先递归销毁其子树
        DestroyTree(root->first_child);

        // 再释放根节点
        free(root);
    }

    // 在目录Dad中，删除目录to_del
    void DirDelete(TreeNode* Dad, TreeNode* to_del) {
        // 函数实现：先把to_del从父节点的孩子链表中摘掉，再销毁以to_del为根的整棵树
        if(Dad == NULL) {
            return;
        }
        // 要删除的就是第一个孩子节点，需要更新first_child指针
        if(to_del == Dad->first_child) {
            Dad->first_child = to_del->next_sibling;;
            // 注意这里不能简单地free(to_del)，因为该目录中可能还有若干目录，目录中可能还有目录，因此要递归销毁。
            DestroyTree(to_del);
            return;
        }

        // 找到要删除的节点的前一个兄弟节点
        TreeNode* pre = Dad->first_child;
        while(pre->next_sibling != to_del) {
            pre = pre->next_sibling;
        }

        // 修改链条，类似单链表的删除操作
        pre->next_sibling = to_del->next_sibling;
        // 注意同样要递归销毁
        DestroyTree(to_del);
        return;
    }
\end{cppcode}

\begin{notebox}{提示}
    以上例子也给了我们一个重要提示：树中每个节点的子节点很多时候不能单纯的看成一个节点，而是要看成一棵子树。因此与树相关的操作，很多都会涉及到递归，这一点非常重要。
\end{notebox}

\subsection{树的一些基本概念与性质}
我们回到逻辑上的数据结构：树。树中有一些大家常用的专业术语与性质，我们在这里列出。\\
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.6\textwidth]{assets/pics_and_ppts/ch4/一棵树.png}
    \caption{}
    \label{fig:一棵树}
\end{figure}

a）树中，一个节点拥有的子树数量称为\term{节点的度}。一棵树中所有节点的度的最大值称为这棵\term{树的度}。

b）树中度为0的节点称为\term{叶子节点}，简称\term{叶节点}。显然叶节点没有孩子节点。不是叶子节点的节点称为\term{非叶节点}。\\
图\ref{fig:一棵树}中，节点A、B的度均为3，整棵树的度为3；节点E、F、K、H、I、L、M的度为0，是叶子节点。\\
c）可以看出树是一种具有层次结构的数据结构。根节点处于最高层，通常定义根为第1层，根的孩子为第2层。若某节点处在第i层，其子树的根节点就处在第i+1层。

d）\term{节点的深度}通常定义为节点的所在层次；而\term{节点的高度}通常是指从最底层叶子节点（高度为1）开始逐层累加至该节点时的高度值。所有节点的深度
的最大值称为\term{树的深度}或\term{树的高度}。即
\begin{bulk}
    \begin{center}
        树的高度 = max\{所有节点的深度值\} = max\{所有节点的高度值\}
    \end{center}
\end{bulk}

图\ref{fig:一棵树}中，节点A的深度为1，高度为4；节点B的深度为2，高度为3；节点K的深度为4，高度为1。整棵树的深度，或称整棵树的高度，为4。

\begin{notebox}{提示}
    1.有些人喜欢将根节点的高度定义为0，本书若无特别说明，默认按照根节点高度为1来定义。\\
    2.注意区分节点与树的深度和高度：节点的高度和节点的深度通常不是一回事；而树的高度和树的深度一定是相等的。
\end{notebox}

e）类似现实中的说法，数据结构中多棵树同样可以构成\term{森林}。

\minisection{树的重要性质}
我们首先给出一个重要性质：对于任何一棵非空树，其节点数$n$与边数$e$一定有
\[
    n = e + 1
\]
成立。显然，当$n=1$时，树只有一个根节点，上式显然成立。此后，如图\ref{fig:节点数等于边数加一规律图}所示，从任何一个节点引出一条新的边，
都会使得边数$e$和节点数$n$同时加一，因此等式仍然成立。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.8\textwidth]{assets/pics_and_ppts/ch4/节点数等于边数加一规律图.png}
    \caption{}
    \label{fig:节点数等于边数加一规律图}
\end{figure}
另外，不难发现，每从节点引出一条新的边，会使边数加一的同时，会使该节点的度数加一，所以不难得知，所以对任何一棵非空树，所有节点的度数之和即等于
该树的总边数$e$。

整理以上两个结论，有：对任何一棵非空树，都有以下结论成立：
\begin{center}
    树的边数e = 树中所有节点的度数之和 = n - 1（n为树的节点数）
\end{center}

\begin{notebox}
    由以上的思维过程也可以反推出一件事：树中度为n的节点，会为树“贡献”n条边。比如：一棵度为3的树，若已知度为3、2、1的节点分别有7、5、8个，则该树的边数一定是
    \[
        7 * 3 + 5 * 2 + 8 * 1 = 39
    \]
    于是可知该树的节点数为$39+1=40$，于是叶节点的数量就是$40-7-5-8=20$个。
\end{notebox}


\section{二叉树的基本内容介绍}
简单地说，“最多两个分叉的树”就是二叉树。一棵普通的二叉树本身通常难以在实际问题中应用上，但是它却是后面一些非常有趣的特殊二叉树（如
\term{二叉查找树}、\term{哈夫曼树}、\term{堆}等）的理论基础。所以我们有必要首先进行一些理论铺垫。
\begin{definitionbox}
    \term{二叉树}要么是一棵空树，要么是一棵：\\
    
    由根节点以及它的两棵子树构成的树，这两棵子树有左右位置之分，分别称为\term{左子树}和\term{右子树}，并且左子树和右子树依然是一棵二叉树。
\end{definitionbox}
可以看到，二叉树是\term{递归定义}的，即用二叉树自身来定义二叉树。
如图\ref{fig:几棵不同的二叉树}所示的几棵树都是二叉树，根据图中文字介绍，大家也能进一步体会二叉树的“递归定义”。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=1.0\textwidth]{assets/pics_and_ppts/ch4/几棵不同的二叉树.png}
    \caption{几棵不同的二叉树}
    \label{fig:几棵不同的二叉树}
\end{figure}
请注意，由图\ref{fig:几棵不同的二叉树}我们可以看出，二叉树的递归定义中，递归边界就是二叉树为一棵空树，这一点对我们二叉树中的诸多编程思想尤其重要，大家在后面
将会慢慢体会到。
显然二叉树的度只可能是0、1或2，二叉树中每一个节点的度也只可能是0、1或2。



\begin{notebox}{提示}
    “二叉树”与“度为2的有序树”有如下区别：\\
    1. 二叉树的度未必是2，还可能是0或1；\\
    2. 二叉树即使只有一个孩子节点，该节点也要区分左右。而度为2的有序树，其“有序”是兄弟之间的位置有序，若某个节点是“独生子女”，则其位置是唯一确定的，不分左右。
    二叉树明确区分孩子的左右位置，这是因为在更多的场景下这是有用的，在后面的内容中我们将有所体会。
\end{notebox}

有两种比较丰满的二叉树需要特别关注：满二叉树与完全二叉树。

如果二叉树中的任意一层节点数都达到了当层能达到的最大节点数，这种二叉树称为\term{满二叉树}；如果除最下面
一层外，其余层都达到了当层最大节点数，并且最后一层的节点都一个挨一个地挤在左边，则二叉树称为\term{完全二叉树}。显然满二叉树一定都是完全二叉树。

图\ref{fig:一些满二叉树与完全二叉树}展示了一些满二叉树与完全二叉树。

\subsection{二叉树的实现}
\label{subsec:二叉树的实现}
\minisection{将二叉树存储为二叉链表}
有了链表的思维，相信大家非常自然地就能想到二叉树的实现方式：树的节点设两个指针分别指向其左孩子和右孩子如下所示：
\begin{cppcode}
    struct BTreeNode {
        ElemType data;
        BTreeNode* lchild;  // 左孩子的指针
        BTreeNode* rchild;  // 右孩子的指针 
    };
\end{cppcode}
这正是二叉树最为经典的实现方式，这种物理结构也称为\term{二叉链表}，它与普通的单链表相比“多分出了一个叉”。

正如本节之初所指出，二叉树的实际应用在于一些有趣的特殊二叉树。人们对队列、栈等数据结构有“入队、出队、入栈”等常见操作的定义，是因为它们切实有用，有
重要的实际意义，而普通二叉树几乎不存在实际应用，因此通常不会为它定义一些常见操作，以上介绍的理论，是为了后面的特殊二叉树服务。此处如果你感兴趣，可以
尝试完成下面的“思考”。

\begin{thinkbox}
    建立一棵你中意的二叉树，并遍历这棵树，打印所有节点的数据内容。
\end{thinkbox}

\minisection{二叉树的顺序存储}
\label{minisec:二叉树的顺序存储}
基于二叉树有上下的层次关系以及左右的次序关系，如果我们从上到之下、从左到右地为二叉树的每一个节点依次编号，就可以将这些
节点依次存储在数组中的对应下标之处，如图\ref{fig:二叉树的顺序存储}所示，我们这里遵循多数人的习惯，根节点从1开始编号，即从数组下标1处开始存储，而非从0。根据规律不难
得出，\textbf{在这种存储方式下，任一节点i，其父节点的编号一定是\(\left\lfloor \frac{i}{2} \right\rfloor\)（前提是i>1, 即该节点有父节点）；并且其左孩子如果存在的话，
编号一定是2i，右孩子如果存在的话，编号一定是2i+1。}
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.95\textwidth]{assets/pics_and_ppts/ch4/用数组表示二叉树.png}
    \caption{二叉树的顺序存储}
    \label{fig:二叉树的顺序存储}
\end{figure}


这种表示法可以由以下代码实现：
\begin{cppcode}
    struct BTreeNode{
        ElemType data;
        int valid;  // 该节点是否存在
    }; 
    BTreeNode nodes[MaxSize];   // 该数组中保存的就是二叉树的所有节点
\end{cppcode}

\begin{notebox}{提示}
    一般情况下每个节点还需要一个字段valid标识是否有效。但如果你存放的数据满足某种特点，比如一定都是正整数，那么你也可以不要valid字段，而是通过将数据的值
    置为，如-1，来表示该位置处节点不存在。
\end{notebox}

二叉树的这种存储方式的问题在于，即使某个节点不存在，也要浪费一个编号位，最坏情况下，当二叉树形状趋于深度为h的一条直线时，我们用约\(2^h\)个空间仅存储了约h个数据。

经过观察不难发现，\textbf{该表示法对完全二叉树（以及满二叉树）非常友好}。因为完全二叉树的节点从上到下、从左到右是连续的，不存在空缺的编号。在介绍{\color{red}
\textbf{后面的内容时}}，我们也能看到该表示法在完全二叉树中的妙用。\\

在进入本章真正有趣的部分之前，我们还要进行一场最后的理论准备：二叉树的遍历。

\subsection{二叉树的遍历}
遍历一个顺序表有多种方式，可以从前向后，也可以从后向前等。类似地，遍历二叉树也有多种方式。常见的、有意义的遍历方式通常有如下4种：\term{层序遍历}、\term{先序遍历}、
\term{中序遍历}、\term{后序遍历}。相信大家最容易想到的遍历方式就是从上到下、从左到右地一个一个节点地访问，这就是\term{层序遍历}。对于
图\ref{fig:用于指出遍历序列的二叉树}中所示的二叉树，层序遍历得到的访问序列是A,B,C,D,E,F,G,H,I,J。

\minisection{二叉树的层序遍历}
对于链式存储的二叉树：
\begin{cppcode}
    struct BTreeNode {
        ElemType data;
        BTreeNode* lchild;  // 左孩子的指针
        BTreeNode* rchild;  // 右孩子的指针 
    };
\end{cppcode}
如何从上到下，从左到右地依次访问每个节点？显然我们仅通过二叉树已有的物理结构是不行的，以图\ref{fig:用于指出遍历序列的二叉树}为例，当我们从A走到B时，
我们知道下一步要访问C，但却没有一种有效的手段优雅地实现接下来的操作。所以我们需要一种手段，每走到一个节点之时，先将其两个孩子按正确的顺序保存起来，它们
就是接下来即将被访问的节点。

承先贤之智，将下法传与思渡者：可使用一个队列，将更上层的节点优先入队，并且确保同层级的节点中，更左边的优先入队。这样，队中节点顺序即是层序遍历的顺序，
依次\uline{出队访问}即可。具体来说，实现二叉树层序遍历的过程如下：
\begin{enumerate}[label=\arabic*）]
    \item 将根节点root加入队列q；
    \item \uline{出队访问}队首节点front\_node；
    \item 如果front\_node有左孩子，先将左孩子入队；
    \item 如果front\_node有右孩子，再将右孩子入队；
    \item 若队列q不空，回到第2）步；否则说明遍历完成，算法结束。
\end{enumerate}
显然第一步将根节点加入队列是毋庸置疑的。而第3）、4）两步，先加入左孩子再加入右孩子，则保证了从左到右的访问顺序。
\begin{insightbox}
    如果你希望从上到下、从\uline{右}到\uline{左}地遍历二叉树，将上面的3）、4）两步交换位置即可。
\end{insightbox}
层序遍历的伪代码如下所示。
\begin{cppcode}
// 对根为root的二叉树进行层序遍历。对每个节点执行visit()函数。
    void LayerOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;
        Queue q;
        InitQueue(q);
        EnQueue(q, root);   // 根节点入队
        while(!Empty(q)) {
            BTreeNode* front_node = NULL;
            DeQueue(q, front_node);     // 队首节点出队，赋值给变量front_node
            visit(front_node);          // 访问front_node
            if(front_node->lchild != NULL) {
                EnQueue(q, front_node->lchild);     // 入队左孩子
            }
            if(front_node->rchild != NULL) {
                EnQueue(q, front_node->rchild);     // 入队右孩子
            }
        }
    }
\end{cppcode}

正是队列的先进先出特性，保证了节点按照从上到下、同层从左到右的顺序被访问。

除层序遍历外，对一棵二叉树的\uline{根节点}、\uline{左子树}和\uline{右子树}也可以有不同的访问顺序。访问一棵二叉树时：
\begin{enumerate}
    \item 若先访问根节点，再访问左子树，最后访问右子树，这种“\uwave{根-左-右}”的遍历方式称为\term{先序遍历}，也称\term{先根遍历}。
    \item 若先访问左子树，再访问根节点，最后访问右子树，这种“\uwave{左-根-右}”的遍历方式称为\term{中序遍历}，也称\term{中根遍历}。
    \item 若先访问左子树，再访问右子树，最后访问根节点，这种“\uwave{左-右-根}”的遍历方式称为\term{后序遍历}，也称\term{后根遍历}。
\end{enumerate}

\begin{notebox}{提示}
    请注意，无论何种访问方式，左子树一定是先于右子树访问。所谓的“先、中、后”指的是“根节点”被“先”访问，还是“中”或“后”访问。
\end{notebox}

\begin{insightbox}
    注意：本内容可能带来一些认知和思维上的启发，但对思渡者来说，可能带来知识记忆上的混乱。\\

    我们为什么不将“根右左”、“右根左”、“右左根”分别定义为先根、中根、后根遍历？这是因为，二叉树的左右子树具有天然的对称性。
    将左与右交换，树的结构和\textbf{本质}并没有发生变化，它描述的还依然是那个“东西”，只是我们人类需要换一个方向去观察和描述它。

    比如你将左边视为头时，[3,5]的\textbf{本质}可以理解为“3在前，5在后的两个数”；而事实上[5,3]同样可以描述“3在前，5在后的两个数”，只需要你把右边视为头，或者
    把“前”定义为后。二者本质相同，只是我们人类观察和理解它的视角不同。

    更进一步地讲，“前”与“后”、“左”与“右”的方向本身就是人为定义的，左子树之所以叫左子树，只是因为我们把“左”定义为了左而已。“左”与“右”本质上并无区别。\\

    我们约定先左，只是因为人类的习惯就是左在前，右在后，这更符合绝大多数人的思维方式。
\end{insightbox}

\minisection{二叉树的先序遍历}
参照图\ref{fig:根节点与左右子树}，先序遍历下，对任何一棵二叉树BT，总是先访问其根节点，再访问其左子树LBT和右子树RBT。递归地，对于LBT和RBT又有同样的规则。
因此递归遍历便是很自然的想法，而递归边界就是某棵子树为空树。先序遍历的递归代码如代码\ref{code:先序遍历二叉树}所示：
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.53\textwidth]{assets/pics_and_ppts/ch4/根节点与左右子树.png}
    \caption{}
    \label{fig:根节点与左右子树}
\end{figure}    

\begin{cppcodeNum}[label={code:先序遍历二叉树}]
    void PreOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;   // 递归边界
        visit(root);    /* 先序遍历，先访问根节点。请注意：这里root应理解为递归过程中访问的每棵子树的根节点，不能仅简单地理解为整棵树的根节点。*/
        PreOrderTravel(root->lchild);   /* 递归遍历左子树。请注意：一定不能写成 visit(root->lchild)。此处场景要把root->lchild看成一棵左子树，而不能仅仅看成一个节点。*/
        PreOrderTravel(root->rchild);   // 递归遍历右子树
    }
\end{cppcodeNum}

返回到E-> B -> A；此时A的左子树已经全部访问完成，根据先序规定的访问顺序：\Circled{1}A\;\Circled{2}A的左子树\;\Circled{3}A的右子树，A及A的左子树已访问完成，接下来访问
A的右子树；\\[0.5em]
走到Tree(C)；\uline{访问C}；\\[0.5em]
走到Tree(F)；\uline{访问F}；\\[0.5em]
走到Tree(I)；\uline{访问I}；\\[0.5em]

\bookmark{bookmark:waypoint-4}{waypoint-4}
可以看出，先序遍历的思想，简单说就是：
\begin{enumerate}
    \item 访问根节点（先根）；
    \item 递归地遍历左子树；
    \item 递归地遍历右子树。
\end{enumerate}
后面的中序、后序遍历，实际上也是这三步，只不过访问根节点的顺序有所不同。\\

请注意，根据先序遍历一定最先访问根节点的特性，对一棵二叉树的先序遍历序列，序列的第一个节点一定是根节点。如上例中，整棵树的遍历序列是
\[
    A,B,D,G,E,H,C,F,I,J
\]
因此A是整棵树的根节点。而对于A的左子树中的五个节点，遍历序列是
\[
    B,D,G,E,H
\]
因此B是该子树的根节点。再如以F为根节点的子树，遍历序列是
\[
    F,I,J
\]
因此F是根节点。

\minisection{二叉树的中序遍历}
参照图\ref{fig:根节点与左右子树}，中序遍历总是先访问左子树，再访问根节点，最后访问右子树。中序遍历的思想与先序遍历类似，只不过在访问根节点之前，要先递归遍历左子树：
\begin{enumerate}
    \item 递归遍历左子树；
    \item 访问根节点（中根）；
    \item 递归遍历右子树。
\end{enumerate}
可以看到，先序、中序、后序在代码上的区别其实就是把“访问根节点”这一操作放在哪一步的区别。中序遍历的代码如下所示。
\begin{cppcode}
    void InOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;   // 递归边界
        InOrderTravel(root->lchild);   
        visit(root);        // 中根
        InOrderTravel(root->rchild);   
    }
\end{cppcode}
我们以图\ref{fig:用于指出遍历序列的二叉树}模拟一遍整个过程。拟用Tree(T)表示以T为根节点的子树。则先序遍历过程如下：\\[0.5em]
走到Tree(A) -> 中根遍历，因此先访问A的左子树，再访问A，最后访问A的右子树。所以暂且不访问A，而是先\\[0.5em]
走到Tree(B) -> 同样地，先访问B的左子树：\\[0.5em]
走到Tree(D) -> 同样地，先访问D的左子树，因此\\[0.5em]
走到Tree(NULL，即D的左孩子) -> 为空树，递归边界，返回到D；该访问D这个节点了：\\[0.5em]
\uline{访问D}，此时D及D的左子树均访问完成，该访问D的右子树了。所以\\[0.5em]
走到Tree(G) -> 依旧先左；
走到Tree(NULL, G的左孩子)；返回到G；\\[0.5em]
\uline{访问G}；此时G及G的左子树均访问完成，该访问G的右子树了。\\[0.5em]
走到Tree(NULL, G的右孩子)；返回到G；\\[0.5em]
返回到D；此时D及D的左右子树均已经访问完成。\\[0.5em]
返回到B；此时B的左子树已访问完成，根据中序遍历规则，该访问根节点了，于是\\[0.5em]
\uline{访问B}；此时B的左子树及B都访问完成，该访问B的右子树了。\\[0.5em]
走到Tree(E)；
走到Tree(H) -> \uline{访问H}；我们不再赘述空子树的访问过程。\\[0.5em]
回到E；\uline{访问E}；\\[0.5em]
回到B -> A；此时A的左子树已经全部访问完成，根据中序规定的访问顺序：\Circled{1}A的左子树\;\Circled{2}A\;\Circled{3}A的右子树，现在A的左子树已经访问
完成，所以接下来\uline{访问A}，然后访问A的右子树。\\[0.5em]
走到Tree(C) -> 左子树为空；\uline{访问C}；\\[0.5em]
走到Tree(F) -> \\[0.5em]
走到Tree(I) -> \uline{访问I}；\\[0.5em]
回到F；\uline{访问F}；\\[0.5em]
走到J；\\[0.5em]
\uline{访问J}；\\[0.5em]
一路回退到A；代码结束。中序遍历得到的序列为D, G, B, H, E, A, C, I, F, J\\

请注意：对于二叉树的中序遍历，根节点的访问总是在左子树和右子树的中间。因此，若已知某棵树的根节点是哪一个，就可以根据根节点在中序序列中的位置，将该中序序列
从根节点处砍成两半，得到左子树和右子树的中序遍历序列。如上面的例子，若已知根节点为A，则立即可以得到：\\
\Circled{1} 根节点左子树的中序遍历序列是
\[
    D, G, B, H, E
\]
\Circled{2} 根节点右子树的中序遍历序列是
\[
    C, I, F, J
\]

\minisection{二叉树的后序遍历}
有了前面的内容，后序遍历就变得很好理解。后序遍历是“左-右-根”，即根节点的访问在最后：
\begin{enumerate}
    \item 递归遍历左子树；
    \item 递归遍历右子树；
    \item 访问根节点（后根）。
\end{enumerate}
代码如下。
\begin{cppcode}
    void PostOrderTravel(BTreeNode* root) {
        if(root == NULL) return ;   // 递归边界
        PostOrderTravel(root->lchild);   // 先递归遍历左子树
        PostOrderTravel(root->rchild);   // 再递归遍历右子树
        visit(root);        // 左子树、右子树均访问完成后，最后访问根节点。
    }
\end{cppcode}
先序遍历是最先访问根节点，而后序遍历是最后访问根节点。因此对后序遍历序列来说，序列中的最后一个节点一定是根节点。
对于图\ref{fig:用于指出遍历序列的二叉树}所示的二叉树，其后序遍历得到的序列为G,D,H,E,B,I,J,F,C,A。\\

% 对于中序遍历得到的序列，在某节点前面的、紧挨着该节点的元素称为该节点的\term{中序前驱}；类似地，在某节点后面的、紧挨着该节点的元素称为该节点的\term{中序后继}。
% 同样二叉树中的节点有\term{先序前驱}、\term{先序后继}、\term{后续前驱}、\term{后续后继}的说法，分别由先序遍历序列、后序遍历序列决定。

18. \\1）通过观察不难发现，对于树中的任意一个节点，其左子树中所有节点的值均小于该节点的值，右子树中所有节点的值均大于该节点的值。\\
2）中序遍历，得到的序列是1, 3, 4, 5, 6, 7, 9, 10, 11, 12；该序列是大小有序的。\\
3）插入节点时，可以从根节点开始，将根节点元素与待插元素比较。若待插元素较小，则说明该节点需要在左子树中插入，此时，若：\\
\Circled{1} 左子树为空，则插入位置已经找到，直接插入；\\
\Circled{2} 左子树非空，则递归地进入左子树，进行同样的操作。\\
反之若待插元素大于根节点，则递归地判断右子树。如此递归进行下去，直至找到正确的位置。具体实现代码如下：
\begin{cppcode}
    void InsertTree(node* &root, int e) {
        if(root == NULL) {
            // 空树，直接插入就行
            node* new_node = (node*)malloc(sizeof(node));
            new_node->data = e;
            new_node->lchild = NULL;
            new_node->rchild = NULL;
            root = new_node;
            return ;
        }
        // e已存在，无需插入
        if(e == root->data) {
            return ;
        }
        if(e < root->data) {   // 待插元素较小
            // 递归地进入左子树
            InsertTree(root->lchild, e);    
        } 
        else if(e > root->data) {    // 待插元素较大
            // 递归地进入右子树
            InsertTree(root->rchild, e);    
        }
    }
\end{cppcode}
事实上，我们将在后面的内容中介绍到，有着这样特点的树叫做\term{二叉查找树}，或者叫\term{二叉搜索树}、\term{二叉排序树}。正如其名，这种数据结构
可以利用节点值之间的大小关系进行较为高效的查找操作，我们将在后面的内容中详细介绍。

\section{哈夫曼树与哈夫曼编码}
\label{sec:哈夫曼树与哈夫曼编码}
请思渡者考虑以下最为经典的“合并柴薪”问题：\\

在初始火焰的熔炉周围，散落着$n$堆柴薪，重量分别为$w_1, w_2, ..., w_n$，你每次可以搬运任意两堆柴薪$i$和$j$，将它们合成一堆重量为$w_i+w_j$的新柴薪，
这个过程需要消耗的体力为$w_i+w_j$。显然，$n-1$次搬运之后，就只剩下一堆柴薪了。请问你能否设计最优的合并次序方案，使得耗费的体力最少？并给出消耗的体力值。

例如有3堆柴薪，重量分别为：
\[
    [3, 6, 11]
\]
第一次，你将6和11合并到一起，消耗体力17，还剩两堆柴薪：
\[
    [3, 17]
\]
第二次，你将3和17合并到一起，消耗体力20，只剩一堆柴薪：
\[
    [20]
\]
合并过程一共消耗了 17 + 20 = 37点体力。 显然，若你先合并3和6，则可以达成更少的体力消耗：(3+6)+(9+11)=29点体力。\\

我们看一个稍微复杂一点的例子，五堆柴薪重量分别是：3, 6, 2, 3, 4。我们先随意将它们合并，看看过程中会发生什么。合并过程可以如图\ref{fig:柴薪的合并过程}所示：
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{assets/pics_and_ppts/ch4/柴薪的合并过程.png}
    \caption{柴薪的合并过程}
    \label{fig:柴薪的合并过程}
\end{figure}

可以看出，一堆柴薪参与合并后，并不会从后续的合并过程中消失，而是会作为新柴薪的一部分，继续参与后续合并。
例如，初始重量为 3 的柴薪与重量为 6 的柴薪合并后，形成一堆重量为 \(9=3+6\) 的柴薪。虽然新柴薪的重量变成了 9，
但其中仍然包含原来重量为 \uline{3} 的柴薪（9=\uline{3}+6嘛）。因此，当这堆重量为 9 的柴薪再次参与合并时，产生的消耗中仍然包含原来那 3 的重量。也就是说：
\textbf{每堆\uline{原始}柴薪在每次参与合并时，都会为总体力消耗贡献一次自己的初始重量。}于是，若初始重量为 \(w_i\) 的柴薪参与了 \(k_i\) 次合并，
那么它对总消耗的贡献就是 \(w_i k_i\)。因此，整个合并过程的总消耗可以表示为
\[
W=\sum_{i=1}^{n}w_i k_i
\]

另一方面，由图\ref{fig:柴薪的合并过程}可以看出，原始柴薪越靠后参与合并，其总共参与的合并次数就越小，如4只参与了1次合并，而3和6却参与了4次合并。因此，自然要将原始重量
更大的柴薪放在更后面合并，这样其参与的合并次数就小，因而总体造成的体力消耗就更小。

基于以上讨论，很容易设计出最优的合并方案：每次从当前所有柴薪中，选出两堆重量最小的进行合并，直至最后合并完成。对于3, 6, 2, 3, 4这五堆柴薪，一种最优的合并
方式如图\ref{fig:柴薪的最优合并方式}所示。

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.45\textwidth]{assets/pics_and_ppts/ch4/柴薪的最优合并过程.png}
    \caption{最优合并过程}
    \label{fig:柴薪的最优合并方式}
\end{figure}
第\Circled{1}步，将最小的2和3合并，消耗体力5，合并后新的柴薪：
\[
    [5, 6, 3, 4]
\]
第\Circled{2}步，将这四堆中最小的3和4合并，消耗体力7，合并后新的柴薪：
\[
    [5, 6, 7]
\]
第\Circled{3}步，将最小的5和6合并，消耗体力11，合并后新的柴薪：
\[
    [11, 7]
\]
第\Circled{4}步，将最小的(也是仅剩的)11和7合并，消耗体力18，合并成最终的一堆柴薪：18。
可以看出，消耗的总体力 = 5 + 7 + 11 + 18 = 41。换个角度，2、3贡献了3次自己的初始重量、6贡献了2次，3和4贡献了2次，因此
$ W=\sum_{i=1}^{n}w_i k_i = (2+3)*3 + 6*2 + (3+4)*2 = 41 $。

相信你早已看出来了，合并的过程其实就构成了一棵二叉树，原始的五堆柴薪就是五个叶子节点，而每堆初始柴薪参与的合并次数$k_i$就是该叶子节点到根节点的\term{路径长度}。
在以上二叉树中，每个节点的数值代表了要搬动这堆柴薪需要消耗的体力。事实上在许多应用中都要类似现象，我们在许多场景下会将树中的节点赋予一个表示某种意义的数值，
称为节点的\term{权}。从树根到一个节点的路径长度与该节点上权值的乘积，就叫做\uline{该节点的}\term{带权路径长度(WPL)}（可以理解为这堆柴薪在后续合并
过程中还会贡献的总体力消耗），而树中所有\uline{叶子节点}的带权路径长度之和就称为\uline{这棵树的}\term{带权路径长度(WPL)}，记为。
\[
\text{WPL}=\sum_{i=1}^{n}w_i k_i
\]
其中$w_i$是第$i$个叶节点的权值，$k_i$是该叶节点到根节点的路径长度。在含有$n$个带权叶节点的二叉树中，带权路径长度最小的二叉树就称为\term{哈夫曼树}。可以看到
在该定义下，“合并柴薪”的问题其实就是求以这n堆柴薪为叶节点的哈夫曼树，其带权路径长度是多少。

通过这个例子，我们也理解了“带权路径长度”以及哈夫曼树的应用价值。图\ref{fig:柴薪的最优合并方式}所示的过程其实也就是由给定的若干个节点，构造一棵哈夫曼树的过程。这里
将该过程完整地叙述如下：
\begin{enumerate}
    \item 初始化。 根据给定的 \(n\) 个权值，构造 \(n\) 棵仅包含一个节点的二叉树，每个节点的权值分别为 \(w_1,w_2,\ldots,w_n\)。
    此时，每棵树都只有一个根节点，且该节点同时也是叶节点。
    \item 选择与合并。 从当前所有二叉树中，选择根节点权值最小的两棵二叉树，将它们合并为一棵新的二叉树。具体而言，
    以一个新节点作为根节点，将选出的两棵二叉树分别作为新根节点的左、右子树，并将新根节点的权值设置为这两棵树的根节点权值之和。
    \item 更新集合。 将刚刚合并得到的新二叉树加入当前的二叉树集合，同时从集合中移除原先被合并的两棵二叉树。这样，集合中的二叉树数量便减少一棵。
    \item 重复执行步骤 2 和步骤 3，直到当前集合中只剩下一棵二叉树。
    \item 得到哈夫曼树。 最终剩下的二叉树就是所构造的哈夫曼树。其所有叶节点的带权路径长度之和最小。
\end{enumerate}

需要注意的是，选择权值最小的两棵树进行合并时，若存在权值相同的节点，可以任选符合条件的两棵树。不同的选择可能构造出形态不同的哈夫曼树，但所得的最小带权路径长度相同。

\minisection{哈夫曼树的性质}
\label{minisec:哈夫曼树的性质}
从以上哈夫曼树的构造过程可以看出哈夫曼树具有如下特点：
\begin{enumerate}
    \item 最初有$n$个叶节点，合并需要$n-1$步，因此新增共$n-1$个节点。所以：\textbf{具有$n$个叶节点的哈夫曼树，其总结点数一定是$n+n-1=2n-1$}。
    \item 所有有孩子的节点一定都是由2棵子树合并而来，因此\textbf{哈夫曼树中不存在度为1的节点}。
\end{enumerate}
这两条性质在某种角度其实是相通的。

\subsection{哈夫曼编码}
我们知道数字信号是一种二值信号，通过有不同特征的电信号来表示0或1。将字符编码成二进制信号，就可以实现数字信号的传输。如最经典的ASCII编码，
\textquotesingle A\textquotesingle 的编码为65，传输过程中的数字信号为 01000001，而\textquotesingle a\textquotesingle 对应的数字信号为 01100001。
这种编码方式是\term{等长编码}，对所有字符的编码长度相等，都是8位，都需要8个bit。
但是，实际应用中，各个字符的使用率却大有差异。例如一篇新闻报道中，\textquotesingle e\textquotesingle 和\textquotesingle \; \textquotesingle（空格）
等字符的数量一定远大于\textquotesingle \$\textquotesingle 和\textquotesingle x\textquotesingle 等字符。

显然，如果我们能够将出现频率更高的字符编码得更短，而频率低的字符编码较长，就可以减少所需的传输空间。

然而这种\term{不定长编码}也带来了一个新的问题：
对方收到之后，如何解码？比如你将A、B、C分别编码为0、1、01，那么收到0101，应解码为ABAB还是ABC或CC？

因此，我们还需要为编码方案增加一个重要的约束：\textbf{任何一个字符的编码，都不能是另一个字符编码的前缀}。满足这一条件的编码称为\term{前缀编码（Prefix Code）}。

\begin{insightbox}
    在诸多英文文献中，\term{前缀编码（Prefix Code）}也被称为“Prefix-free Code”，即“无前缀编码”。笔者认为后者在语义上更加直观。
\end{insightbox}

于是问题就变成了：给定n个字符$c_1, c_2, ..., c_n$及它们的权重（即字符出现的次数）$w_1, w_2, ..., w_n$，求一种前缀编码方案让总编码长度达到最小。

我们可以借助二叉树来解决这样的编码问题。我们规定从根节点向左走代表数字 $0$，向右走代表数字 $1$。如图\ref{fig:用二叉树进行不定长编码}所示，
这样，从根节点到任意节点的路径，就可以用一串二进制数字表示。如果我们将每个字符放在一片叶节点上，那么从根节点到该叶节点的路径，就可以作为这个
字符的编码，路径长度也即是编码长度。该例中，A的编码为000，到根节点的路径长度为3，即是编码长度；B的编码为01，路径长度、编码长度为2；C的编码为1。

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.47\textwidth]{assets/pics_and_ppts/ch4/用二叉树进行不定长编码.png}
    \caption{用二叉树进行不定长编码}
    \label{fig:用二叉树进行不定长编码}
\end{figure}

假设字符 $c_i$ 出现的次数为 $w_i$，其在二叉树中对应叶节点的深度为 $k_i$，
则传输所有字符所需的总比特数为
\[
    L=\sum_{i=1}^{n} w_i k_i
\]
而这恰好就是该树的带权路径长度（WPL）。因此，在字符及其出现次数固定的情况下，使总编码长度最小，等价于使二叉树的带权路径长度最小。因此求解该问题，实际上就是
构造哈夫曼树的过程。例如，A, B, C, D, E五个字符出现次数依次是3, 6, 2, 3, 4，则可以构造如图\ref{fig:哈夫曼编码}所示的哈夫曼树。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.5\textwidth]{assets/pics_and_ppts/ch4/哈夫曼编码.png}
    \caption{哈夫曼编码}
    \label{fig:哈夫曼编码}
\end{figure}

A、B、C、D、E的编码与长度如下：
\begin{center}
    \begin{tabular}{|c|c|c|}
        \hline
         & 编码值 & 编码长度/路径长度\\
        \hline
        A & 001 & 3\\
        \hline
        B & 01 & 2\\
        \hline
        C & 000 & 3\\
        \hline
        D & 10 & 2 \\
        \hline
        E & 11 & 2 \\

    \end{tabular}

同时，由于叶节点不可能是其他节点的祖先，因此，任何一个字符的编码都不会成为另一个字符编码的前缀。这恰好满足了前缀编码的要求。这种由哈夫曼树产生的编码称为
\term{哈夫曼编码}。显然对于相同字符集存在多种哈夫曼编码，但它们的编码长度是相同的。

在“合并柴薪”问题中，一堆柴薪参与合并的次数越多，它的重量就会在总代价中被累加越多次；在“字符编码”问题中，一个字符的编码越长，它消耗的传输空间就越多。
二者共同的底层逻辑是：\textbf{每个对象都有自己的权值，而我们可以通过不同的安排，决定这个权值会被计入最终结果多少次。}

\begin{thinkbox}
    对于“合并柴薪”问题，你能否写出一个函数，输入一组重量，输出最优的体力消耗值（只要输出这个数值就行）？
\end{thinkbox}
通过上面的思考你也许会发现，解决此类问题并不需要真的构造出一棵哈夫曼树。编码问题亦是如此，同样不需要在计算机中存储哈夫曼树。事实上，哈夫曼树的意义在于，对于这类问题，
它为我们提供了统一的数学模型和统一的求解方法。

还有一个问题，以“合并柴薪”问题为例，我们需要每次从当前所有柴薪堆中选出两个重量最小的，合并后再放回去。使用什么数据结构保存柴薪堆，能使这个操作达到最快？显然若使用普通线性表，
对于频繁插入删除的场景，链表一定更好。选择两个最小、合并后再插入的时间可以达到O(n)。

我们在接下来的介绍中将看到，如果使用\term{堆}保存所有柴薪的重量，这个选择加合并后插入的过程可以达到O(logn)。如果你熟悉C++，应该已经想到了使
用一个std::priority\_queue来保存所有柴薪堆，实际上，C++标准库中的priority\_queue正是通过\term{堆}来实现的。

\section{堆}
\term{堆}是一棵完全二叉树，满足其中任何一个节点的关键字的值都不大于（或不小于）其左右子树中任何一个节点的关键字的值。完全二叉树的根节点称为\term{堆顶}。若任何一个节点的值都不
大于其左右子树，这样的堆叫做\term{最小堆}，也叫\term{小顶堆}或\term{小根堆}，堆顶元素一定是堆中最小的；若任何一个节点的值都不小于其左右子树，
这样的堆叫做\term{最大堆}，也叫\term{大顶堆}或\term{大根堆}，堆顶元素一定是堆中最大的。图\ref{fig:最小堆和最大堆}
（左）和（右）分别展示了一个最小堆和一个最大堆。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.81\textwidth]{assets/pics_and_ppts/ch4/最小堆和最大堆.png}
    \caption{}
    \label{fig:最小堆和最大堆}
\end{figure}

请注意：以最大堆为例，最大堆能保证：
\Circled{1}根节点一定是最大的；\;
\Circled{2}任何一个节点，都比其左右子树中的节点大。\;但是最大堆无法保证上层节点一定大于下层节点，因为它们不一定处于同一棵子树中。如图\ref{fig:最小堆和最大堆}（右）中，节点39虽处于第4层，但它比第3层的13、0还要大。

\begin{insightbox}
    关键字（Key）可以理解为用于标识数据或确定数据比较关系的一个或多个数据项。 在排序等问题中，通常根据关键字的值来确定数据的大小关系。例如，对于字符
    数据，可以将其 ASCII 码值作为关键字；对于游戏中的武器数据，可以将武器的id或攻击力作为关键字。
\end{insightbox}

\subsection{堆及其常见操作的实现}
由于堆是一棵完全二叉树，因此用一个数组顺序存储就非常合适（参见\ref{minisec:二叉树的顺序存储}，第\pageref{minisec:二叉树的顺序存储}页）。
使用数组存储一个堆也是最常见、最方便的实现方式。通常情况下通过一个数组和一个整数，就可以表示一个堆：
\begin{cppcode}
    int heap[MaxSize+1];
    int size = 0;  // 堆中元素的数量
\end{cppcode}
注意我们定义根节点编号为1，从数组下标1开始存储。显然这种存储方式下，heap[1]就能获取堆顶元素的值，时间复杂度为O(1)。

为了方便大家建立对堆的感觉，我们先来看如何将一个已有若干元素的完全二叉树（数组存储）调整成一个堆。本节所有对堆操作的介绍均以\uline{最大堆}为例。
假设数组arr[]中已经存储了完全二叉树的n个节点，可以通过如下操作将这个完全二叉树调整成一个堆：
\minisection{将完全二叉树调整为堆}
从编号为$ \left \lfloor \frac{n}{2} \right \rfloor $ 的节点，即最后一个非叶子节点开始，逐一向前检查每一个节点，对每个节点
进行\term{向下调整}操作。将节点\term{向下调整}是指，将该节点与其两个孩子（若存在）中较大的那个比较，若该节点小于较大的那个孩子，
则将该节点“下沉”，与较大的那个孩子交换位置。交换后，该节点到了新的位置，继续检查能否继续“下沉”，直到该节点沉入某个无法继续与孩子
交换的位置，或沉到叶节点。我们以图\ref{fig:建堆操作初始树}所示的完全二叉树为例，介绍详细的流程。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.59\textwidth]{assets/pics_and_ppts/ch4/建堆操作初始树.png}
    \caption{}
    \label{fig:建堆操作初始树}
\end{figure}

从一个已有的完全二叉树建堆的过程如代码\ref{code:堆的向下调整及建堆代码}所示。注意在向下调整的函数DownAdjust()中，while循环终止有两种可能，一是2*i 已经大于 n 了，
即该节点已经调整到了叶子节点，没有孩子了；二是该节点已经调整到了某位置，其值不小于两个孩子中更大的那个了，无需继续下沉。
\begin{cppcodeNum}[label={code:堆的向下调整及建堆代码}, codetitle={堆的向下调整及建堆代码}]
// 元素数量为n的完全二叉树中，将编号为 i 的元素向下调整
    void DownAdjust(int arr[], int n, int i) {
        // i表示下沉过程中，该节点已经“沉入”到了编号为多少的地方。
        // 最后一个节点编号是n，因此2*i<=n表示该位置还有子节点
        while(2*i <= n) {
            int max_child = arr[2*i];   // 先假设左孩子是更大的
            int max_child_idx = 2*i;
            // 事实上右孩子存在，且右孩子更大
            if(2*i+1 <= n && arr[2*i+1] > arr[2*i]) {
                max_child = arr[2*i+1]; 
                max_child_idx = 2*i+1;
            }
            // 该元素较小，应该继续下沉 
            if(arr[i] <= max_child) {
                int t = arr[i];
                arr[i] = arr[max_child_idx];
                arr[max_child_idx] = t;
                i = max_child_idx;
            } 
            // 已经不满足继续下沉的条件，向下调整完成。
            else {
                break;
            }
        } 
    }
// 将具有n个元素，存储在arr[]数组中的完全二叉树调整成一个堆。
    void CreateHeap(int arr[], int n){
        for(int i=n/2; i>=1; i--) {
            DownAdjust(arr, n, i);
        }
    }
\end{cppcodeNum}
向下调整，至多需要“下沉”约logn次，时间复杂度为O(logn)。而对于建堆操作，需要将约n/2个元素向下调整，每个元素向下调整的时间复杂度为O(logn)，那整个
建堆过程就是O(nlogn)。

\minisection{向上调整、向堆中插入元素}
要往堆中加入一个元素，可以先将该元素放在数组尾部（即完全二叉树的最后一个节点后面），再将该元素\term{向上调整}。与向下调整类似，\term{向上调整}就是将该节点
不断地与其父节点比较，若大于父节点，则将该节点“上浮”，与父节点交换位置，之后不断重复该操作，直至不满足上浮条件，或已经上浮到根节点，如此，该节点的向上调整
就完成了。向上调整与插入操作的代码实现如\ref{code:向上调整及插入操作}所示。

\begin{cppcodeNum}[label={code:向上调整及插入操作}, codetitle={向上调整及插入操作}]
// 元素数量为n的完全二叉树中，将编号为 i 的元素向上调整
    void UpAdjust(int arr[], int n, int i) {
        // i表示上浮过程中，该节点已经上浮到了编号为多少的地方。
        while(i/2 > 0) {    // 此位置还有父节点
            int father_idx = i/2;
            if(arr[i] > arr[father_idx]) {
                int t = arr[i];
                arr[i] = arr[father_idx];
                arr[father_idx] = t;
                i = i/2;
            }
            else {
                break;
            }
        }
    }
    // 向当前有n个元素的堆arr中，插入新元素e
    void InsertHeap(int arr[], int& n, int e) {
        n += 1;
        arr[n] = e;
        UpAdjust(arr, n, n);
    }
\end{cppcodeNum}
与向下调整类似，向上调整的时间复杂度同样为O(logn)。显然插入操作的时间复杂度也是O(logn)。

\minisection{删除堆顶元素}
要删除堆顶元素，只要用\term{堆底元素}，即完全二叉树的最后一个节点，覆盖掉堆顶元素，然后将新的堆顶向下调整即可。如代码\ref{code:删除堆顶元素}所示。
\begin{cppcodeNum}[label={code:删除堆顶元素}, codetitle={删除堆顶元素}]
    void DeleteTop(int arr[], int& n) {
        if(n == 0) return ;
        arr[1] = arr[n];
        n -= 1;
        DownAdjust(arr, n, 1);
    }
\end{cppcodeNum}
显然删除堆顶元素的操作时间复杂度为O(logn)。\\

注意以上所有操作都是以最大堆为例来介绍的。最小堆的操作类似。

\subsection{堆的经典应用}
下面介绍一些堆的经典的、最常见的应用场景。
\minisection{1.动态维护最大值或最小值}
堆的一个重要价值在于，能够在数据不断变化时，以 O(logn)的时间复杂度插入和删除元素，并以O(1)的时间复杂度获取当前的最大值或最小值，也就是能高效地动态维护优先级最高的元素。
例如在\ref{sec:哈夫曼树与哈夫曼编码}（第\pageref{sec:哈夫曼树与哈夫曼编码}页）中介绍的“合并柴薪”以及“字符编码”问题，需要不断地从容器中删除两个最小的，合并
之后再插入容器，这种问题非常适合使用堆来实现。

一个比较有趣的事情是，{\color{red}\textbf{在后面的介绍中我们将看到}}，求解最短路径的大名鼎鼎的迪杰斯特拉算法，使用堆可以进一步提升性能。

\minisection{2.找出大量数据中最大或最小的k个}
例如，如果需要从10万件商品中，筛选价格最低的k件商品，最朴素的做法是对这10万件商品遍历k次，第i次遍历找出第i小的价格。但是这需要某种手段标记i之前已经
被找到了的元素。算法时间复杂度为O(nk), 并且需要额外空间。

如果使用排序算法，{\color{red}\textbf{我们将在后面的内容中介绍到}}，最好可以达到O(nlogn)的时间将这10万件商品排成一个有序的列表，再取前k件即可。时间复杂
度为O(nlogn)，空间复杂度最好（堆排序）为O(1)。

一种更巧妙的做法是，我们建立一个具有k个元素的\textbf{最大堆}，保存10万个元素中最小的k个，让这100000个元素“争抢进入这个堆的权利”，谁更小，谁就能进入堆中。
显然，只要某个元素至少小于堆中的某一个元素，该元素即可进入堆中。而事实上对最大堆来说：
\begin{bulk}
    \begin{center}
        至少小于一个元素 => 小于堆顶元素    一定成立\\[0.6em]
        小于堆顶元素 => 至少小于一个元素    一定成立\\[0.6em]
        因此至少小于一个元素 <=> 小于堆顶元素
    \end{center}
\end{bulk}
因此我们逐一检查这100000个元素，将它们依次与堆顶元素进行比较，若小于堆顶元素，说明该元素是当前检查过的所有元素里前k小的，此时若堆已满，令其覆盖堆顶元素并调整堆，
保证堆顶依然是堆中最大的；若堆未满，直接将其加入堆中。直至检查完所有元素，堆中保存的，即是这所有10万个元素中最小的k个元素。

该方法需要对所有n个元素进行一遍访问，每次访问可能需要对堆进行调整，对于有k个元素的堆，调整堆的复杂度为O(logk)，因此整体时间复杂度为O(nlogk)。与排序算法可以达到
的O(nlogn)相比，有所提升。同时该方法需要一个额外的k个空间的辅助堆，空间复杂度为O(k)。

            for(int i=0; i<n; i++) {
                min_heap.push(w[i]);
            }
            // 做n-1次
            for(int i=1; i<=n-1; i++) {
                // 取出两个重量最小的：w1和w2
                int w1 = min_heap.top();
                min_heap.pop();
                int w2 = min_heap.top();
                min_heap.pop();

                // 体力消耗为w1+w2
                int union_cost = w1 + w2;
                total_cost += union_cost;
                
                // 合成一堆后放回堆中
                min_heap.push(union_cost);
            }
            return total_cost;
        }
    \end{cppcode}

    不难发现，每棵子树T的WPL等于其左子树与右子树的WPL之和。因此求T的WPL，可以递归地转化为求T->lchild以及T->rchild的WPL。递归边界就是左子树或右子树为空树。
    代码如下所示。
    \begin{cppcode}
        int WPL(node* root, int depth) {
            // 空树，直接返回0
            if(root == NULL) return 0;
            // 当前递归到的，以root为根节点的子树，其左右子树都是空树，因此root的WPL可以直接计算。
            if(root->lchild == NULL && root->rchild == NULL) {
                return root->weight * (depth-1);    // 深度为depth的节点，根节点到其路径长度为depth-1
            }
            // root还有子树，需要递归地计算子树的WPL并加到一起，作为root的WPL返回
            int total = 0;    
            if(root->lchild != NULL) {
                total += WPL(root->lchild, depth+1);
            }
            if(root->rchild != NULL) {
                total += WPL(root->rchild, depth+1);
            }

            return total;
        }
    \end{cppcode}
    调用WPL(T, 1)即可求出T的带权路径长度。注意：我们这里按照惯例，将根节点深度定义成了1，这恰好能正确处理“只有一个根节点的树”的情况。\\

            if(root == NULL) return 0;

            // 叶子节点，出口找到了 
            if(root->lchild == NULL && root->rchild == NULL) {
                return root->weight;
            }
            // 左边是死路，只能从右边走
            if(root->lchild == NULL) {
                return root->weight + MinEscapeCost(root->rchild);
            }
            // 右边是死路
            if(root->rchild == NULL) {
                return root->weight + MinEscapeCost(root->lchild);
            }

            // 两边都能走，递归计算两边代价后，选代价小的那一条路
            int ltree_cost = MinEscapeCost(root->lchild);
            int rtree_cost = MinEscapeCost(root->rchild);

            return root->weight + min(ltree_cost, rtree_cost);
        }

\section{二叉查找树}

在一组混乱、无序的线性表中查找关键字为某值的数据，平均时间复杂度为O(n)。若数据存放在有序的顺序表中，使用二分查找平均时间复杂度可以达到O(logn)。但是顺序表难以维护动态数据：
当表中元素增加或删除时，需要移动大量元素，移动操作的平均时间复杂度为O(n)。

二叉查找树的思想类似二分查找，将元素通过某种有序的方式组织起来，以达到较为高效的元素查找效率。经过本节的研究我们将看到，
在二叉查找树中查找元素的\uline{平均}时间复杂度为O(logn)，插入、删除元素的\uline{平均}时间复杂度同样是O(logn)。

\begin{definitionbox}
    \term{二叉查找树}要么是一棵空树，要么是：\\

    一棵由根节点、左子树和右子树构成的二叉树，其中左子树和右子树均是二叉查找树，并且左子树上所有节点的关键字均小于根节点的关键字，右子树上所有节点的
    关键字均大于根节点的关键字。
\end{definitionbox}
图\ref{fig:几棵不同的二叉查找树}展示了几棵不同的二叉查找树。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.78\textwidth]{assets/pics_and_ppts/ch4/几棵不同的二叉查找树.png}
    \caption{几棵不同的二叉查找树}
    \label{fig:几棵不同的二叉查找树}
\end{figure}
可以看到，二叉查找树其实是一种\uline{有序}的树形结构。二叉查找树具有“左小、根中、右大”的特征，而按照中序遍历“左-根-右”的方式遍历二叉查找树，得到
的序列就是一个有序序列。

二叉查找树最重要的意义就在于在动态变化的数据中较为高效地进行查找，如前文所述，其查找、插入和删除均能达到O(logn)的平均时间复杂度。接下来我们就来看看如何实现这些操作。

\subsection{二叉查找树的实现}
通常情况下，二叉查找树同样采用二叉链表实现：
\begin{cppcode}
    struct BSTreeNode { // Binary Search Tree
        ElemType data;  
        BSTreeNode* lchild;
        BSTreeNode* rchild;
    };
\end{cppcode}
为不引入额外的理解负担，我们假设data已经是某种可以比较大小的数据结构，data本身即作为关键字。

\minisection{1.查找操作}
如何在二叉查找树T中，查找关键字值为e的元素？

由于二叉查找树的特点，根节点其实作为分界线，将左右两棵子树划分成了“两个界域”，若e的值大于根节点，则它不可能出现在左子树中，如图\ref{fig:根节点划分界域}，
直接递归地在右子树中查找即可。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.58\textwidth]{assets/pics_and_ppts/ch4/根节点划分界域.png}
    \caption{}
    \label{fig:根节点划分界域}
    
\end{figure}

类似地，若e更小，则它不可能出现在左子树中。因此在二叉查找树中查找元素，不必像无序线性表那样将所有元素遍历一遍，而是可以舍弃掉大量元素的比较，因此效率更高。
如果e存在，一定会在查找过程中找到。如果e不存在，则递归一定会进行到某个空节点。


具体来说，查找过程如下：从根节点开始，
\begin{enumerate}
    \item 若当前节点为空，说明查找失败，返回；否则进入第2步。
    \item 若e的值等于当前节点，说明查找成功，访问它；
    \item 若e的值小于当前节点，说明应该往左，因此递归地在当前节点的左子树中查找；
    \item 若e的值大于当前节点，说明应该往右，因此递归地在当前节点的右子树中查找。
\end{enumerate}
代码如下所示：

\begin{cppcode}
    int BSTSearch(BSTreeNode* root, ElemType e) {
        if(root == NULL) {
            return 0;   // 查找失败，e不存在
        }
        if(e == root->data) {
            visit(root);    // 找到了，做你想对它做的事吧！
            return 1;   // 查找成功
        }
        if(e > root->data) {
            return BSTSearch(root->rchild, e);
        }
        if(e < root->data) {
            return BSTSearch(root->lchild, e);
        }

    }
\end{cppcode}

\minisection{2.插入操作}
插入节点时，可以从根节点开始，将根节点元素与待插元素比较。若待插元素较小，则说明该节点需要在左子树中插入，此时，若：\\
\Circled{1} 左子树为空，则插入位置已经找到，直接插入；\\
\Circled{2} 左子树非空，则递归地进入左子树，进行同样的操作。\\
反之若待插元素大于根节点，则递归地进入右子树。如此递归进行下去，直至找到正确的位置。具体实现代码如下：

\begin{cppcode}
    void InsertBSTree(node* &root, int e) {
        if(root == NULL) {
            // 空树，直接插入就行
            node* new_node = (node*)malloc(sizeof(node));
            new_node->data = e;
            new_node->lchild = NULL;
            new_node->rchild = NULL;
            root = new_node;
            return ;
        }
        // e已存在，无需插入
        if(e == root->data) {
            return ;
        }
        if(e < root->data) {   // 待插元素较小
            // 递归地进入左子树
            InsertBSTree(root->lchild, e);    
        } 
        else if(e > root->data) {    // 待插元素较大
            // 递归地进入右子树
            InsertBSTree(root->rchild, e);    
        }
    }
\end{cppcode}

\minisection{3.由已有数据建立二叉查找树}
假设数组arr[]中存放了n个数据，用这些数据建立一棵二叉查找树的过程，其实就是将它们一一插入二叉查找树的过程。代码如下所示：
\begin{cppcode}
    BSTreeNode* CreateBSTree(ElemType arr[], int n) {
        BSTreeNode* root = NULL;
        for(int i=0; i<n; i++) {
            InsertBSTree(root, arr[i]);
        }
        return root;
    }
\end{cppcode}
需要注意的是，即使是同样的一组数据，如果插入它们的顺序不同，也可能生成不同的二叉查找树。例如插入顺序为{1,2,3,4,5,6,7,8,9}，会得到一棵“斜向右下的一条直线”的树，深度
为9；而插入顺序为{9,8,7,6,5,4,3,2,1}，树形则会是“斜向左下的一条直线”。


\minisection{4.删除操作}
在二叉查找树T中删除关键字为e的节点，如何做？

与插入操作不同，插入操作一定能“陷入”一棵空树作为插入位置，而对于删除操作，被删节点很可能还有复杂的子树。显然：

\Circled{1} 对于待删节点是叶节点，直接释放掉该节点即可。

\Circled{2} 若待删节点是非叶节点，该怎么办呢？常见的做法是找到待删节点的\term{中序前驱}或\term{中序后继}，用中序前驱或中序后继覆盖掉待删节点，
然后问题便转化成了递归地在左子树中删除中序前驱，或在右子树中删除中序后继，如此向子树递归、向子树的子树递归、向子树的子树的子树递归......
总会将问题\uwave{化归}为\Circled{1}，即待删节点是叶节点。

在二叉查找树中，比某节点小的最大节点一定是中序遍历序列中，该节点的前驱，称为该节点的\term{中序前驱}，相应地，比某节点大的最小节点称为该节点的\term{中序后继}。
显然，节点的中序前驱一定是该节点左子树中最右边的节点（也就是从左子树根节点开始不断沿着rchild往右下走，直到rchild为NULL时的节点），而节点的中序后继一定是
该节点右子树中最左边的节点（也就是从右子树的根节点开始不断沿着lchild往左下走，直到lchild为NULL时的节点）。如图\ref{fig:中序前驱和中序后继}所示，节点12的
中序前驱是11，中序后继是13。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.89\textwidth]{assets/pics_and_ppts/ch4/中序前驱和中序后继.png}
    \caption{}
    \label{fig:中序前驱和中序后继}
\end{figure}

我们先给出两个辅助函数，用于寻找节点的中序前驱和中序后继：
\begin{cppcode}
// 寻找节点node的中序前驱
    BSTreeNode* FindInOrderPre(BSTreeNode* node) {
        // 该节点没有中序前驱，或中序前驱不存在于子树中
        if(node->lchild == NULL) {
            return NULL;
        }
        BSTreeNode* ret = node->lchild;
        while(ret->rchild != NULL) {
            ret = ret->rchild;
        }
        return ret;
        
    }
// 寻找节点node的中序后继
    BSTreeNode* FindInOrderPost(BSTreeNode* node) {
        // 该节点没有中序后继，或中序后继不存在于子树中
        if(node->rchild == NULL) {
            return NULL;
        }
        BSTreeNode* ret = node->rchild;
        while(ret->lchild != NULL) {
            ret = ret->lchild;
        }
        return ret;
        
    }
\end{cppcode}

根据上面的讨论，我们给出在二叉查找树T中删除关键字为e的节点的详细思路：

\Circled{1} 如果e大于当前节点，说明待删元素在右子树中，递归地在右子树中删除e；

\Circled{2} 如果e小于当前节点，类似地，递归地在左子树中删除e；

\Circled{3} 如果当前节点为空（NULL），说明树中不存在关键字为e的元素，直接返回即可；

\Circled{4} 如果e等于当前节点，说明找到了要删除的节点，进入删除操作：

a）若当前节点是叶节点，直接删除即可；

b）若当前节点有左孩子，那么可以在左子树中寻找节点的中序前驱pre，用pre的数据覆盖掉当前节点的数据，之后在左子树中删除节点pre；

c）若当前节点有右孩子，那么可以在右子树中寻找节点的中序后继post，用post的数据覆盖掉当前节点的数据，之后在右子树中删除节点post。

完整的删除代码如下所示：
\begin{cppcode}
// 在树root中，删除值为e的节点
    void DeleteBSTree(BSTreeNode* &root, ElemType e) {
        if(root == NULL) {
            return ;
        }
        if(e < root->data) {
            DeleteBSTree(root->lchild, e);
        }
        if(e > root->data) {
            DeleteBSTree(root->rchild, e);
        }
        if(e == root->data) {
            // root是叶节点
            if(root->lchild == NULL && root->rchild == NULL) {
                BSTreeNode* to_free = root;
                // root = NULL是为了改变链条，让其父节点的孩子指针指向NULL
                root = NULL;
                free(to_free);
            }
            // root不是叶节点
            else {
                // 有左子树
                if(root->lchild != NULL) {
                    // 若有左子树，则一定能找到中序前驱，所以pre一定不是NULL
                    BSTreeNode* pre = FindInOrderPre(root);
                    root->data = pre->data;
                    DeleteBSTree(root->lchild, pre->data);
                } 
                // 有右子树
                else if(root->rchild != NULL) {
                    BSTreeNode* post = FindInOrderPost(root);
                    root->data = post->data;
                    DeleteBSTree(root->rchild, post->data);
                }
            }
        }
    }
\end{cppcode}

\section{平衡二叉树}
在上一节中，可能你已经想到了，当我们使用序列{1,2,3,4,5,6,7,8,9}来构造一棵二叉查找树时，形成的树形是斜向右下的一条直线，高度为9。此时，二叉查找树实际上退化为
了一个线性表。许多具有类似结构特点的二叉查找树对查询、插入等操作带来的优化非常有限。

那么我们能不能在每次插入、删除元素后对树加以调整，让结构依然保持平衡？
例如当插入1到9时，对树进行如图\ref{fig:1到9插入调整过程}所示的调整。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=1.0\textwidth]{assets/pics_and_ppts/ch4/1到9插入调整过程.png}
    \caption{}

这样，二叉查找树始终能保持高效的，O(logn)级别的操作。基于这样的思想，两位先贤，名为G.M.\textbf{A}delse-\textbf{V}elskil以及
E.M.\textbf{L}andis提出了\term{平衡二叉树}，也被称为\term{AVL树}。AVL树是满足“平衡”要求的二叉查找树。所谓平衡，是指对树中任意节点来说，其左右子树的高度相差
不超过1。

对于一个节点，其左子树的高度减去右子树的高度，差值称为该节点的\term{平衡因子}（可以将节点理解为天平的中点，将其左右子树的高度分别理解为左右托盘的砝码数量）。
于是我们知道，\term{平衡二叉树要求树中任何一个节点的平衡因子的绝对值不超过1}。

图\ref{fig:1到9插入调整过程}中，c）调整前，节点1的左子树为空树，高度为0，右子树高度为2，因此节点1的
平衡因子为0-2=-2，左右子树高度相差2，不是平衡二叉树，而调整后，节点2、1、3的平衡因子都是0，因此是一棵平衡二叉树。
显然树中只要存在一个节点平衡因子的绝对值超过1，该树就不是平衡二叉树，因此我们需要一种手段记录每个节点的平衡因子。通常的做法并不是直接在节点的结构定义中记录平衡因子，
而是记录以当前节点为根节点的子树的高度：
\begin{cppcode}
    struct AVLTreeNode {
        ElemType data;
        AVLTreeNode* lchild;
        AVLTreeNode* rchild;
        int height;     // 以该节点为根的子树的高度。
    }
\end{cppcode}
\begin{notebox}{提示}
    height一定要理解为以该节点为根的子树的高度，为简洁不啰嗦，本节中我们表达为“节点高度”，但一定要将height理解为树的高度。
\end{notebox}

于是某节点的平衡因子就可以通过其左右子树高度之差计算得来。
\begin{cppcode}
// 返回节点root的平衡因子
    int GetBalance(AVLTreeNode* root) {
        int lheight;    // 左子树高度
        int rheight;    // 右子树高度

        // 注意不能直接通过root->lchild->height获取子树高度，若root没有左子树，应认为其左子树高度为0.
        if(root->lchild == NULL) {
            lheight = 0;
        }
        else {
            lheight = root->lchild->height;
        }
        if(root->rchild == NULL) {
            rheight = 0;
        }
        else {
            rheight = 0;
        }
        return lheight - rheight;
    }
\end{cppcode}
为了此处及后续诸多地方的代码书写简洁，我们封装一个函数来获取节点的高度：
\begin{cppcode}
    int GetHeight(AVLTreeNode* root) {
        if(root == NULL) return 0;
        return root->height;
    }
\end{cppcode}
于是获取平衡因子的函数就可以简单写成：
\begin{cppcode}
    int GetBalance(AVLTreeNode* root) {
        int lheight = GetHeight(root->lchild);
        int rheight = GetHeight(root->rchild);
        return lheight - rheight;
    }
\end{cppcode}

显然，当我们在平衡二叉树中插入一个新的节点之后，只需要更新该节点的所有\term{祖先节点}的height值，而非祖先的height是不受该新节点的影响的，无需更新。
如图\ref{fig:1到9插入调整过程}e），插入5后，节点1的height无需更新。由于节点root的height等于其左子树的height与右子树的height的较大值加一，
因此当新节点插入后，可以自下而上依次地更新新节点的每一个祖先节点的高度，通过如下函数：
\begin{cppcode}
    void UpdateHeight(AVLTreeNode* root) {
        int lheight = GetHeight(root->lchild);
        int rheight = GetHeight(root->rchild);
        root->height = max(lheight, rheight) + 1;
    }
\end{cppcode}

\begin{insightbox}
    实际上，有了前面二叉查找树插入操作的递归思想，你可能会想得到，“当新节点插入后，自下而上依次地更新每一个新节点的祖先节点的高度”，
    这个更新操作的时机就是在函数递归调用，找到正确的插入位置并插入元素之后再“回溯”到访问该节点的函数栈中时。大家可以结合后面平衡二叉树的插入代码体会。
\end{insightbox}


显然，平衡二叉树的查找操作与二叉查找树没有区别。而平衡二叉树的删除操作较为复杂，一般不做讨论。接下来我们就来重点研究平衡二叉树的插入操作。

\subsection{平衡二叉树的插入操作}
事实上图\ref{fig:1到9插入调整过程} c）所进行的调整，可以称为“进行了以节点1为根的\term{左旋}”。平衡二叉树的插入操作需要视情形对某些节点进行\term{左旋}或\term{右旋}。
我们先来看相关概念。
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.91\textwidth]{assets/pics_and_ppts/ch4/左旋过程示意图.png}
    \caption{左旋过程示意图}
    \label{fig:左旋过程示意图}
\end{figure}
如图\ref{fig:左旋过程示意图}所示的过程将以节点A为根的子树进行了向左的旋转，具体过程如下：
\begin{enumerate}[label=\arabic*）]
    \item 让B的左子树$T_2$成为A的右子树；
    \item 让A成为B的左子树；
    \item 将根节点设定为节点B。
\end{enumerate}
像这样的，将原本的根节点A的右孩子“提升”为新的根节点，并且将A及其左子树“向左下沉”的操作，可以称为（以A为根节点的）\term{左旋}。
在后面的描述中我们简单地称为\textbf{对节点A左旋}。对root左旋的代码如下所示：
\begin{cppcode}
// 对节点root左旋
    void LRotate(AVLTreeNode* &root) {
        AVLTreeNode* tmp = root->rchild;
        root->rchild = tmp->lchild; // 步骤一
        tmp->lchild = root;     // 步骤二
        UpdateHeight(root);     // 先更新下层节点，在更新上层节点
        UpdateHeight(tmp);
        root = tmp;     // 步骤三
    }
\end{cppcode}
注意，$T_1$、$T_2$、$T_3$的height无需更新，因为旋转过程中这三棵树并未发生改变，他们的树高不变。A、B节点的height表示的是以A、B为根节点的子树的高度，这两棵子树
发生了变化，因此需要自下而上地先更新A的高度，再更新B的高度。

相应地，\term{右旋}是与左旋对称的过程，图\ref{fig:右旋过程示意图}展示了对节点B右旋的过程。
\begin{figure}[htbp]

\end{figure}
类似地可以写出代码：
\begin{cppcode}
// 对节点root右旋
    void RRotate(AVLTreeNode* &root) {
        AVLTreeNode* tmp = root->lchild;
        root->lchild = tmp->rchild;
        tmp->rchild = root;
        UpdateHeight(root);
        UpdateHeight(tmp);
        root = tmp;
    }
\end{cppcode}

以上介绍的左旋和右旋操作，正是用于失衡的调整。已经被证明，若失衡，我们只需要把新插入节点的所有祖先节点中，
最靠近新插入节点的那个失衡节点调整到正常，则路径上的所有节点就都会平衡。而最靠近新插入节点的失衡节点，其失衡的情形一定是

至此，我们来总结一下平衡二叉树的插入方法。首先，像普通二叉查找树的插入一样，沿着树递归向下找到插入位置，插入节点之后，
沿递归向上返回，判断每一个节点是否存在失衡，若失衡，判断失衡类型（LL、LR、RL、RR）并进行正确的调整即可。沿递归回去的路径判断失衡，第一个找到的失衡节点恰是
距离新插入节点最近的祖先节点。具体实现代码如下。

\begin{cppcode}
    void AVLTreeInsert(AVLTreeNode* &root, ElemType e) {
        // 找到了插入位置，插入
        if (root == NULL) {
            root = (AVLTreeNode*)malloc(sizeof(AVLTreeNode));
            root->data = e;
            root->height = 1;
            root->lchild = NULL;
            root->rchild = NULL;
            return;
        }
        // 关键字已存在，无需插入
        if(e == root->data) {
            return ;
        }
        // 在左子树中插入，只可能是LL型或LR型失衡
        if(e < root->data) {
            AVLTreeInsert(root->lchild, e);
            UpdateHeight(root);
            // 存在失衡
            if(GetBalance(root) == 2) {
                if(GetBalance(root->lchild) == 1) { // LL型失衡
                    RRotate(root);
                } else if(GetBalance(root->lchild) == -1) { // LR型失衡
                    LRotate(root->lchild);
                    RRotate(root);
                }
            }
        }
        // 在右子树中插入，只可能是RR型或RL型失衡
        else if(e > root->data) {
            AVLTreeInsert(root->rchild, e);
            UpdateHeight(root);
            // 存在失衡
            if(GetBalance(root) == -2) {
                if(GetBalance(root->rchild) == 1) { // RL型
                    RRotate(root->rchild);
                    LRotate(root);
                } else if(GetBalance(root->rchild) == -1) { // RR型
                    LRotate(root);
                }
            }
        }
    }
\end{cppcode}

\begin{insightbox}
    事实上，根据实际场景的不同需求，可能会需要允许重复关键字的树。绝大多数参考资料对此不做讨论，作为拓展，笔者给出一种较为简单的实现思路：\\

    在每个节点中增加一个链表，将所有相同关键字的数据存储起来：
    \begin{cppcode}
        struct node {
            int key;    // 关键字   
            LinkList<ElemType> datas;  // datas是一个链表，保存所有关键字为key的数据。
            node* lchild;
            node* rchild;
            int height;
        };
    \end{cppcode}
    这样，插入时，和链表中第一个节点比较即可。若相等，将新元素插入链表尾部。

\end{insightbox}
显然平衡二叉树的查找、插入操作的时间复杂度均为O(logn)。有了以上插入操作的实现，通过已有的n个元素构建一棵平衡二叉树，只需要依次将这n个元素插入树中即可。代码如下：
\begin{cppcode}
// 将存储在arr中的n个元素建立一棵平衡二叉树，返回树的根节点
    AVLTreeNode* CreateAVLTree(ElemType arr[], int n) {
        AVLTreeNode* root = NULL;
        for(int i=0; i<n; i++) {
            AVLTreeInsert(root, arr[i]);
        }
        return root;
    }
\end{cppcode}

7. 我们从根节点开始，向左右子树寻找两个目标节点。如果发现左边找到了一个、右边也找到了一个，那么当前节点一定是它们的最近公共祖先。完整代码如下：
\begin{cppcode}
    node* LowestCommonAncestor(node* root, int a, int b) {
        if( root == NULL ) return NULL;

        if( root->key == a || root->key == b ) return root;

        node* left = lowestCommonAncestor(root->left, a, b);
        node* right = lowestCommonAncestor(root->right, a, b);
        if( left != NULL && right != NULL ) return root;
        if( left ) return left;
        if( right ) return right;

        return NULL;
        
    }
\end{cppcode}
寻找公共祖先的代码是极难理解的。别急，我和大家一起慢慢将其拆解。建议大家结合下面的代码注释以及图中所示例子的查找过程共同来理解。
首先我们从根节点开始，向左右子树寻找两个目标节点。如果
发现左边找到了一个、右边也找到了一个，那么当前节点一定是它们的最近公共祖先：
\begin{cppcode}

    node* left = LowestCommonAncestor(root->lchild, a, b);
    node* right = LowestCommonAncestor(root->rchild, a, b);

    if (left != NULL && right != NULL)
        return root;
\end{cppcode}
如果沿途找到了某NULL节点，说明此条路径上没有有意义的信息，直接返回NULL；

若找到了某待查关键字，或两个关键字的公共祖先之后，则将相应指针沿路径向上返回：
\begin{cppcode}
// 沿路径查找到了NULL，说明该路径上不存在有用的信息。
    if( root == NULL ) return NULL;

    node* left = LowestCommonAncestor(root->lchild, a, b);
    node* right = LowestCommonAncestor(root->rchild, a, b);

// 若找到了某待查关键字，将该节点指针向上返回
    if( root->key == a || root->key == b ) return root;

// 这种情况成立，则一定是left和right分别是待查找的两个关键字的指针。此时root就是公共祖先，向上返回，一直传递上去。
    if (left != NULL && right != NULL)
        return root;

    // 此前（更下层的递归中）存在有用的信息（左子树中有待查关键字，或已经在左子树中找到了最近公共祖先），将该有用的信息向上返回，传递上去
    if(left) return left;
    // 此前（更下层的递归中）存在有用的信息（右子树中有待查关键字，或已经在右子树中找到了最近公共祖先），将该有用的信息向上返回，传递上去
    if(right) return right;

    // 若左右子树都不存在有用的信息，返回NULL，表示这条路径上没有有用的信息。
    return NULL;
\end{cppcode}
left、right实际上有两层含义：

第一层：未找到公共祖先时，left或right表示该节点左（右）子树中待查找的关键字的指针。（第一种有用的信息）

第二层：找到公共祖先后，left及right的含义就是该节点的左（右）子树中是否存在要找的公共祖先节点，若存在，left或right表示的就是公共祖先节
点的指针，若不存在，left或right为NULL。（第二种有用的信息）\\[0.3em]


我们给出在下图所示的二叉树中，寻找4和5的公共祖先的过程。

第一步，当前节点root是 1，它既不是 4，也不是 5。
因此，算法继续向下查找：\\
- 左子树：从节点 2 开始。\\
- 右子树：从节点 3 开始。\\

第二步：进入节点 2，
节点 2 又会向左右子树查找：\\
- 左边进入节点 4。\\
- 右边进入节点 5。

当递归来到节点 4 时，发现它就是目标节点，于是直接返回节点 4。
同理，来到节点 5 时，直接返回节点 5。
于是，节点 2 这一层得到：
\begin{center}
    node* left = LowestCommonAncestor(root->lchild, 4, 5);       // left是节点4的指针 \\
    node* right = LowestCommonAncestor(root->rchild, 4, 5);     // right是节点5的指针
\end{center}
两边都不为空！说明两个目标节点分别出现在节点 2 的左右子树中。
因此，返回节点 2。\\

第三步：返回节点 1，
节点 2的递归函数中 返回了节点 2，意味着节点 1 的左侧查找结果是节点 2。
而节点 3 的子树里没有 4 或 5，所以右侧返回 nullptr。
因此，节点 1 得到：
\begin{center}
    node* left = LowestCommonAncestor(root->lchild, 4, 5);       // left是节点2的指针 \\
    node* right = LowestCommonAncestor(root->rchild, 4, 5);     // right是NULL
\end{center}
因为只有左边有结果，节点 1的递归函数栈中 就把左边的结果（节点2的指针）继续返回。
得到最终答案是节点 2。\\

8. 事实上有两点可以优化：\\
1）若a和b与某节点相比一大一小，则该节点一定就是最近公共祖先，而无需继续向下找a和b；\\
2）a和b都更大或都更小时，无需两棵子树都进行递归，拿到left和right的信息，而是直接进入lchild或rchild即可。 

此外，由于查找结点一定存在，而在二叉查找树下由上面的2），我们能确定每次递归进入的路径下方一定存在公共祖先，因此一定不会进入NULL节点。
\begin{cppcode}
    node* LowestCommonAncestor(node* root, int a, int b) {
        // a和b分别在root的左右子树中，root就是最近公共祖先
        if(a < root->key && b > root->key) return root;
        if(a > root->key && b < root->key) return root;

        // root就是a或b，root一定是最近公共祖先
        if(root->key == a || root->key == b) return root;
        // a和b都在左子树或都在右子树中，递归地进入左子树或右子树。
        if(a > root->key && b > root->key) return LowestCommonAncestor(root->right, a, b);
        return LowestCommonAncestor(root->left, a, b);
    }
\end{cppcode}

9. 中序遍历中，第k个访问的节点就是树中第k小的元素。因此我们可以在中序遍历过程中，用一个变量visited\_num记录当前已经有多少个节点被访问过了。
当访问到某节点使得 visited\_num == k 时，返回该节点即可，代码如下。

\begin{cppcode}
    void InOrderTravel(node* root, int k, int& visited_num, int& result) {
        if(root == NULL) return ;
        InOrderTravel(root->lchild, k, visited_num, result);

        // 代码执行到此处时，才是中序遍历中“访问”一个节点的时候
        visited_num += 1;
        if(visited_num == k) {
            result = root->val;
            return ;
        }
        // 若visited_num已经>=k，说明找到了，无需继续递归遍历了。
        if(visited_num < k) {
            InOrderTravel(root->rchild, k, visited_num, result);
        }
    }
    int kthSmallest(node* root, int k) {
        int result = 0;
        int visited_num = 0;
        InOrderTravel(root, k, visited_num, result);
        return result;
    }
\end{cppcode}

10. 相信一定有人的思路是这样：遍历一遍所有节点i，判断：其左孩子（即2i）小于节点i的值，并且其右孩子（即2i+1）大于节点i的值，若存在一个节点该条件不成立，则返回false。
否则返回true。事实上，这种思路是错误的。如图，
\begin{center}
    \includegraphics[width=0.35\textwidth]{assets/pics_and_ppts/ch4/22408错误思路示例.png}
\end{center}
以上思路能保证B<A、B<C成立，但不能保证C<A成立。正确的做法是：\\

【解法一】遍历一遍所有节点，不能只判断其左右孩子，而是要判断其左子树中的最大值是否满足小于该节点的值、右子树中的最小值是否满足大于该节点的值。只有所有
节点都满足以上条件，才是一棵二叉搜索树。

我们维护两个数组：local\_min[]和local\_max[]，local\_min[i] 和 local\_max[i] 的值分别表示以节点i为根的子树中的最小值和最大值。从后向前遍历一遍所有节点，
判断是否满足二叉搜索树条件的同时，更新这两个数组。具体过程请参见代码及注释。

\begin{cppcode}
    bool IsBST(SqBiTree tree) {
        // local_max[i]、local_min[i]分别表示以i为根的子树中元素的最大、最小值
        int local_max[MAX_SIZE];
        int local_min[MAX_SIZE];
        // 每个节点为根的子树，其中最大或最小值至少是它们自己
        for(int i=0; i<MAX_SIZE; ++i) {
            local_min[i] = local_max[i] = tree.SqBiTNode[i];
        }

        for(int i=tree.ElemNum; i>=1; i--) {
            int lchild_idx = 2*i;
            int rchild_idx = 2*i+1;

            // 节点i有左孩子
            if(lchild_idx <= tree.ElemNum && tree.SqBiTNode[lchild_idx] != -1) {  
                if(tree.SqBiTNode[i] <= local_max[lchild_idx]) {    // 当前节点的值小于等于左子树中的最大值，不符合条件，返回false
                    return false;
                }
                // 以该节点i为根的子树中的最小值更新为i的左子树中的最小值。
                local_min[i] = local_min[lchild_idx];
            }

            // 节点i有右孩子
            if(rchild_idx <= tree.ElemNum && tree.SqBiTNode[rchild_idx] != -1) {    
                if(tree.SqBiTNode[i] >= local_min[rchild_idx]) {    // 当前节点的值大于等于右子树中的最小值，不符合条件，返回false
                    return false;
                }
                // 以该节点i为根的子树中的最大值更新为i的右子树中的最大值。
                local_max[i] = local_max[rchild_idx];
            }
        } // end for()
        
        // 以上for循环结束，说明所有节点均满足二叉搜索树的条件，返回true。
        return true;
    }
\end{cppcode}


\vspace{\baselineskip}

【解法二】本题还有一种更简单的解法：根据二叉搜索树中序遍历一定是有序的，我们在中序遍历的过程中，记录当前访问的节点i的中序前驱的值pre，若存在某个节点，
其值小于等于pre，则返回false。

\begin{cppcode}
    void InOrderTravel(SqBiTree tree, int i, int& pre, bool& ans);

    bool IsBST(SqBiTree tree) {
        // 先假设是二叉搜索树，若遍历过程发现不满足，将ans置为false。
        bool ans = true;
        // 树中节点都是正整数，因此将第一个节点的前驱初始化为0或任意负数即可。
        int pre = -10;
        InOrderTravel(tree, 1, pre, ans);
        return ans;
    }

    void InOrderTravel(SqBiTree tree, int i, int& pre, bool& ans) {
        // 节点不存在，直接返回
        if(i > tree.ElemNum || tree.SqBiTNode[i] == -1) return;
        // 已经可以做否定断定，无需继续遍历
        if(ans == false) return ;

        // 先访问左子树
        InOrderTravel(tree, 2*i, pre, ans);

        // 若当前访问节点小于等于其前驱，说明不是二叉搜索树
        if(tree.SqBiTNode[i] <= pre) {
            ans = false;
            return;
        }
        // 将下一个待访问节点的中序前驱更新为当前节点
        pre = tree.SqBiTNode[i];

        // 访问右子树
        InOrderTravel(tree, 2*i+1, pre, ans);
        return;
    }
\end{cppcode}
